TTFT 背板:a-Si / LTPS / Oxide 怎麼選

每顆畫素底下都有 TFT 當開關(OLED 還要當電流閥)。通道材料決定電子跑多快(遷移率)、關掉時漏多少、能做多大片:

  • a-Si(非晶矽):遷移率約 0.5~1 cm²/V·s。製程最簡單、大片玻璃也均勻、最便宜;電流小,只夠當 LCD 的電壓開關。長時間偏壓或照光會讓 Vth 漂移。→ 大尺寸 TV、一般 LCD。
  • LTPS(低溫多晶矽):用雷射退火把 a-Si 結晶成多晶矽,遷移率約 50~100 以上。TFT 可以做很小 → 開口率高、PPI 高,還能把部分驅動電路直接做在面板上。代價:晶界讓各顆 Vth 不一致(OLED 要加補償電路)、光罩道數多、雷射退火限制基板尺寸、關閉漏電偏大。→ 手機 LCD / OLED。
  • Oxide(氧化物,IGZO 為代表):遷移率約 10~30。非晶結構 → 大面積均勻;關閉漏電極低,畫面不動時可降到很低的刷新率省電;產線可由 a-Si 線改造。缺點是對水氣、氫、光照敏感,要靠鈍化層保護。→ 大尺寸 OLED TV、高解析平板 / 筆電。
  • LTPO:手機把兩者混用 —— 需要大電流的地方用 LTPS,開關用 Oxide 壓低漏電,所以能在 1~120 Hz 之間變頻。

判斷口訣:要便宜大片 → a-Si;要小要快 → LTPS;要大片又要省電 → Oxide。OLED 一定要電流夠 → 不用 a-Si(見「LCD vs OLED」)。

tTiming 參數:porch、sync 與 pixel clock

一列、一幀都不是只有「看得到的畫素」,前後還留了空白時間給驅動換行、閘極切換、資料準備:

一列(單位:pixel clock)
|Hsync|H back porch|   H active(1920)   |H front porch|
|<------------------- Htotal ------------------------>|
一幀(單位:line)
|Vsync|V back porch|   V active(1080)   |V front porch|
|<------------------- Vtotal ------------------------>|
  • sync width:同步脈波寬度,告訴接收端「新的一列 / 一幀開始」。
  • back porch:sync 之後、有效畫面之前的空白;front porch:有效畫面之後、下一個 sync 之前的空白。兩者合稱消隱期(blanking)。
  • pixel clock = Htotal × Vtotal × 幀率。例:1080p60 常見時序 Htotal 2200、Vtotal 1125 → 2200 × 1125 × 60 = 148.5 MHz。
  • 要改幀率又不想動 pixel clock,常見做法是拉長 V front porch(Vtotal 變大)—— 可變刷新率就是這樣調的。
  • DE mode 的面板只看 DE(資料有效)訊號,不看 Hsync / Vsync;但 porch 太短,driver 來不及換行或預充,會出現邊緣錯位、末列異常。

這些數字存在 EEPROM / driver IC 暫存器裡,規格書的 timing table 就是在列 min / typ / max。

CCOF / COG:驅動 IC 怎麼接到面板
  • 軟板(COF,Chip on Film):driver IC 以覆晶接在 PI(聚醯亞胺)薄膜上,薄膜上有銅走線;薄膜可以彎到面板背面 → 窄邊框。高腳數時用雙面銅。COG(Chip on Glass):IC 直接壓在玻璃邊緣,少一段薄膜、便宜,但玻璃要留邊放 IC、重工難。
  • bonding 兩段:ILB(inner lead bonding)把 IC 的金凸塊熱壓到薄膜內引腳;OLB(outer lead bonding)把薄膜外引腳用 ACF 熱壓到面板玻璃的 pad(ACF 原理見 D02 接合技術)。常見不良:對位偏移、導電粒子夾不到 → 開路或高阻;壓合溫度不均 → 間歇性線缺陷。
  • pin map:定義「IC 輸出通道 → 薄膜走線 → 面板 pad」的對應與順序。輸出端每根接一條 data line(source)或 gate line;輸入端接 T-CON 來的 mini-LVDS 差動對、電源、控制訊號。對錯的症狀:資料線順序反 → 左右鏡像或 RGB 錯色;某段錯位 → 豎條紋、色偏;相鄰兩顆 IC 的通道少接或重疊 → 豎線、黑帶;電源腳接錯 → 不開機、IC 發燙。核對時要同時看面板 datasheet、IC 通道數、fan-out 圖。
  • trace:薄膜上的細間距銅線(inner lead 間距約 20 µm 上下,outer lead 較寬)。面板端的 fan-out 走線長短不一 → RC 不同 → 要做等長或補償;細線怕反覆彎折斷線、濕氣下金屬遷移;輸入端的高速差動對要控制阻抗。
PPMIC / 電源:面板要的各種電軌

面板不是只吃一個電壓。PMIC 用升壓(boost)與電荷泵,從主電源做出好幾條軌,分別餵 source、gate 與面板:

  • AVDD(類比正電,約 +6~+18V)→ source driver 的 DAC / 輸出級,決定灰階電壓滿幅。
  • VGH(閘極導通,約 +15~+30V)、VGL(閘極關閉,約 −7~−15V)→ gate driver / level shifter,把 TFT 開到飽和、關到不漏。
  • VCOM(共同電極)→ 面板背電極;液晶看的是「像素電壓 − VCOM」,可微調抑制 flicker。
  • 另有 half-AVDD、邏輯 VDD(1.2~3.3V)等小軌。

電荷泵(charge pump):只用電容和開關「搬電荷」—— 先把電容充到 VIN,再把它疊在 VIN 上面輸出 → 約 2×VIN;接法反過來 → 約 −VIN;多級串起來就得到更高或更負的電壓。不用電感、便宜體積小,但帶載能力與效率有限、負載越大漣波越大 → 適合電流小的軌:VGH / VGL(閘極只需替 gate line 充放電,平均電流小)。電流大的 AVDD 則用電感式 boost。driver IC 常內建 charge pump 自己產生 VGH / VGL。

上電順序很關鍵:大致 VDD → AVDD → VGL → VGH → VCOM → 開訊號,關機反過來;順序錯會讓驅動 IC/TFT 受異常偏壓甚至 latch-up,所以常由 PMIC 內建時序或 T-CON 控制。

EEEPROM / Flash:面板的「設定檔」

同型號的 IC + 面板,靠這顆非揮發記憶體存每片產品的客製參數,開機由 T-CON 經 I2C/SPI 讀出載入:

  • Gamma 曲線(每個灰階對應的參考電壓)。
  • Timing:解析度、front/back porch、刷新率、各控制訊號相位。
  • VCOM 值與極性反轉模式。
  • driver IC 暫存器初始值、上電順序參數。
  • (外接 scaler 板還會存 EDID 給主機讀。)

所以改 EEPROM 內容就能微調同一塊硬體的 gamma / VCOM / timing,不必動 IC。

I²C 在這裡怎麼用:T-CON 當主控,開機經 I²C 從 EEPROM(常見 24Cxx,7-bit 位址 0x50 一帶)讀出參數;也用 I²C 寫 PMIC、gamma IC、driver IC 的暫存器(設定電壓、gamma 抽頭);產線調 VCOM、gamma 後再寫回 EEPROM / OTP。協定本身(位址、ACK、開汲極)見 L01 I²C／SPI。

I輸入介面:畫面怎麼進到這塊板

主機(SoC/GPU)的畫面用高速序列介面送進來 —— 在這個資料率下,平行匯流排會有太多線與雜訊:

  • V-by-One (HS):大尺寸/高解析常用,差動對少、時脈內嵌。
  • eDP:筆電/平板常見,封包化、可省電。
  • LVDS:較舊、頻寬有限;MIPI-DSI:手機小尺寸。
  • MIPI DSI 細節:實體層 D-PHY,1 對時脈 + 1~4 對資料 lane。每條 lane 有兩種狀態:HS(高速、小擺幅差動,傳畫面)與 LP(低速單端,傳命令、省電、可回讀)。兩種操作模式:Video mode 主機持續送像素流與同步封包,面板端不需 frame buffer;Command mode 主機只在畫面變動時寫入,driver IC 內建 GRAM 自己刷新,較省電(手機 AMOLED DDIC 常見)。設定 driver IC 用 DCS 命令,例如 0x11 sleep out、0x29 display on。

進板後 T-CON 解出畫面,再用面板內部介面(Mini-LVDS / RSDS 等)+ 控制訊號(STV/CKV/POL…)分送給各顆 source driver —— 就是往 COF 那條排線在跑的東西。

偏偏光板 × 液晶:光閥的真正原理

「電壓控制透光量」的機關是三層夾心:下偏光板先把背光變成單一方向的偏振光,液晶依電壓決定要不要把偏振方向「扭」過去,與下片互相垂直的上偏光板只放行被扭過 90° 的光。

  • 電壓在 0 與最大之間 → 只扭一部分 → 透一部分光 = 灰階。這才是「光閥」開大關小的物理機制。
  • TN 沒電壓時是亮(常白);VA / IPS 分子預設排列不同,沒電壓時是暗(常黑)——這就是左欄註腳說「亮暗可能相反」的原因(見「TN / VA / IPS」)。
  • 非偏振的背光過下偏光板,先天就損失約一半亮度——穿透率低的第一站(見「穿透率與開口率」)。
  • 驗證法:戴偏光太陽眼鏡看螢幕再歪頭 90°,畫面會變黑——你的眼鏡就是「第三片偏光板」。
液TN / VA / IPS:三種液晶「排隊方式」

同樣是光閥,液晶分子的預設排列與轉動方向不同,就分出三大家族,各有取捨:

TN扭轉向列。反應最快、最便宜;但視角差(斜看變色反白)、黑色偏灰。入門電競螢幕常見。
VA垂直配向。分子站立,沒電壓時光完全過不去 → 黑最純、對比最高(3000:1 以上);視角中等、反應偏慢。電視主流。
IPS橫向電場,分子在平面內旋轉。視角最廣、色彩最準;對比中等(約 1000:1),邊角易漏光(IPS glow)。手機 / 筆電 / 設計用螢幕主流。

「常白 / 常黑」也影響故障長相:常白面板 TFT 斷路傾向出亮點,常黑面板傾向出暗點(見「壞點與線缺陷」)。

光穿透率與開口率:背光的亮度都損耗到哪?

背光發出 100% 的光,最後到你眼睛只剩個位數 %。一路被誰吃掉:

  • 開口率:每顆子畫素裡 TFT、儲存電容、data / gate 走線都不透光;解析度越高、畫素越小,不透光部分佔比越大 → 開口率越吃緊。
  • 彩色濾光片是最大殺手:白光到紅色子畫素,綠與藍全被吸掉,只留約 1/3 再打折。
  • 所以同亮度下,高解析面板更耗電;背光才要用 DBEF 之類的膜回收偏振損失(見「背光 BLU」)。
  • OLED 沒有這串損耗鏈(不用背光、不用擋光),但有自己的發光效率與壽命問題(見「LCD vs OLED」)。
燈背光模組 BLU:那盞「白燈」的內部

背光不是一塊發光板,而是「光源 + 一疊光學膜」的三明治(側入式,由下往上):

  • 白光哪來的:白光 LED = 藍光 LED + 黃(或紅+綠)螢光粉;螢光粉或量子點(QD)配方決定光譜純度 = 色域上限(見「色彩與色域」)。
  • 直下式(direct-lit):LED 平鋪在整個背面 → 厚一點但亮度高,而且可以「分區」。
  • Local dimming / mini-LED:直下式切成幾百~數千區,畫面暗部直接把該區背光關掉 → 對比逼近 OLED;分區太少會在亮物周圍看到光暈(blooming)。
  • 亮度控制:T-CON / 主機用一條 PWM 線調背光;PWM vs DC 調光的差異見「小知識」。
色色彩與色域:紅綠藍能調出哪些顏色

三原色像三角形的三個角,面板能顯示的所有顏色 = 三角形的內部。三角形有多大(色域),取決於三個角的顏色有多「純」:

  • 色域由「背光光譜 × 濾光片」決定:普通白 LED 的紅綠不夠純 → 約蓋到 sRGB;換 KSF 螢光粉或量子點(QD)讓紅綠光譜變窄變純 → 蓋到 DCI-P3 / Adobe RGB。
  • 白平衡 / 色溫:調 R:G:B 的比例;標準白是 6500K。出廠校色其實就是把修正後的 gamma / 增益寫進 EEPROM(見「EEPROM / Flash」)。
  • 10-bit 與 HDR:10-bit = 每通道 1024 階,漸層更順(對照「位元深度 / FRC」);HDR 還要求更亮的高光與更黑的暗部 → 需要高亮度背光 + local dimming 配合。
  • 灰階(gamma)管「多亮」,這一段管「多紅多綠多藍」——兩者合起來才是完整的色彩鏈。
OLCD vs OLED:兩種點亮方式

LCD 是「常亮的燈 + 幾百萬個擋光閥」;OLED 是「幾百萬顆自己會發光的小 LED」。結構差在:

  • 驅動方式不同:LCD 的 TFT 是電壓開關(1T1C,寫完就保持);OLED 要持續供電流,至少 2T1C——一顆選畫素、一顆當「電流閥」,亮度對 TFT 特性極敏感,所以用 LTPS / 氧化物 TFT,還要加補償電路抵消不均。
  • 沒有的東西:背光、液晶、彩色濾光片(RGB 蒸鍍款)、下偏光板全免 → 更薄、可彎摺;但仍留一片圓偏光板吸掉環境光反射。
  • 代價:有機材料會老化 → 燒屏(常駐圖示印在螢幕上),藍色老最快;低亮度靠 PWM 調光,頻閃比 LCD 明顯。
  • 訊號鏈的前半段(SoC → T-CON → driver)兩者概念相同,差別集中在「畫素怎麼發光」這一站。
修壞點與線缺陷:從症狀反推哪裡壞

面板是「格子 + 橫直線 + 驅動」的結構,所以故障長相直接對應壞掉的位置:

  • 一個點恆亮 / 恆暗:該子畫素的 TFT 短路或斷路。常白面板(TN)壞掉傾向亮點、常黑(VA / IPS)傾向暗點。
  • 一條橫線:某條 gate 線斷、或 GOA 那一級壞 → 該列永遠沒被寫入。
  • 一條直線:某條 data 線斷、或 COF 對應通道壞 → 該行拿不到電壓。
  • 一整塊 / 半邊異常、彩色雜訊:某顆 COF 壓接不良(摔機常見)、或 T-CON → COF 排線問題。
  • Mura(雲斑、亮度不均):cell gap / 配向 / 背光不均——製程等級的問題,不是哪根線斷。
  • 全黑但斜照手電筒隱約有畫面:背光壞了,面板其實還在動;全白 / 無畫面:T-CON 沒送資料或排線脫落。
KKickback(ΔVp)與 VCOM 微調:flicker 從哪來

電源板上那顆「VCOM 微調」存在的理由:gate 關斷的瞬間,畫素電壓會被偷走一小截。

  • 機制:TFT 的 gate 與畫素之間有寄生電容 Cgd;gate 從 VGH 摔到 VGL 時,經電容耦合把畫素電壓拉低 ΔVp ≈ Cgd/(Cgd+Cst+Clc) × (VGH−VGL)。
  • 為什麼變 flicker:正、負半週都被往「下」拽 → 相對 VCOM 一邊變近一邊變遠,兩幀亮度不同,以極性反轉頻率閃動。
  • 解法:把 VCOM 整體往下移 ΔVp,恢復對稱——就是「VCOM 微調」;調好的值寫進 EEPROM。加大 Cst 也能稀釋 ΔVp。
  • 維修換過 T-CON 或面板後常要重調 VCOM,原因就在每片面板的 ΔVp 都略有不同。

✓ 排成網格:只要 5,760 條直線(資料)+ 1,080 條橫線(閘極)= 6,840 條。
做法:閘極驅動(GOA)選一列 → 資料驅動(COF)同時把這一列每個點的顏色灌進去,一列一列輪流,每秒 60 遍。這正是下一段要送的訊號。

小知識
  • 壞點 / 亮線:一個恆亮或恆暗點 = 一顆子畫素的開關壞了;一整條亮 / 暗線 = 一條 data / gate 線或它的驅動壞了。完整判讀表見目錄「壞點與線缺陷」。
  • 為何要極性反轉:長期同極性會讓液晶老化、產生殘影,所以每幀 / 每行翻正負(以 VCOM 為準)。
  • LCD vs OLED:LCD 用背光 + 液晶光閥;OLED 每個子畫素自己發光,不需背光與液晶,黑就是真的關掉。
  • 速度感:60Hz = 每秒 60 張;1080 列要在約 16ms 內掃完,平均一列只有十幾微秒。
  • 高刷新率 / VRR:120Hz = 每秒重畫 120 張,一列時間再砍半(對充電更嚴苛)。VRR(FreeSync / G-Sync)讓刷新率跟著顯卡出圖速度浮動,治畫面撕裂;此時 Overdrive 要按當下幀率換補償表,做不好會出現反向鬼影。
  • 調光與頻閃:背光亮度用 PWM(高速開關,佔空比調亮暗)或 DC(直接降電流)。PWM 頻率太低部分人會覺得眼睛疲勞;DC 調光在低亮度則容易偏色。
★更多核心觀念(互動)
Gamma 校正

數位灰階值不是線性對應亮度。Gamma 把 0–255 的「碼」彎成亮度,讓人眼敏感的暗部分到更多階、避免色帶。拉 γ 看變化。

γ2.20
γ≈2.2 是 sRGB 常見值;γ=1 為線性(無校正)。實機會再配合面板特性微調。
極性反轉(對 VCOM)

液晶不能長期吃同方向電壓(會老化、殘影),要相對 VCOM 正負交替(AC 驅動)。不同反轉法在畫質與功耗間取捨,選一種看每幀怎麼翻。

紅 = +(高於 VCOM)、藍 = −(低於 VCOM),每幀整體翻一次。
畫素記憶(取樣保持)

每個畫素其實是一個小電容。閘極一開,把資料電壓充進去;閘極一關,電容把電壓「記住」整整一幀,所以掃描間畫面不會熄。拉 V 設定要寫入的電壓。

V
綠 = 畫素電容電壓(決定亮度)。閘極(黃)每幀只開一下,其餘全靠電容保持;改 V 要等下一次閘極開才寫入。
位元深度 / FRC

每個顏色通道用幾個位元,決定能分幾階:8-bit = 256 階。位元太少,漸層會出現一條條色帶。FRC 用相鄰兩階在時間上快速交替,讓眼睛「平均」出更多階。

低位元時打開 FRC,色帶被「抖」平滑(畫面其實在高速閃動,眼睛看平均)。這就是 6-bit 面板「偽 8-bit」的做法。
反應時間 / Overdrive

液晶轉向需要時間;畫面在動時來不及轉到位 → 拖影 / 鬼影。Overdrive 把電壓推過頭一點,讓液晶更快到位、縮短拖影。

亮塊由左往右移,後面的尾巴就是拖影。打開 Overdrive,尾巴明顯變短。
子畫素渲染

一張圖就是一格格畫素值;每個畫素其實是紅、綠、藍三條直條。放大就看到「白 = 三條全亮、黃 = 紅+綠」。換圖案、切換放大看子畫素。

掃描成像(逐列畫出)

整張畫面是一列一列「畫」出來的:閘極選到第幾列,資料就把那一列填上。看它由上往下成形,或單步觀察。

黃色是「正在寫入」的列;上面已寫、下面未寫(暗)。一張寫完從頭再來——每秒重複 60 次。

對應 taxonomy E01～E06。L1是什麼 L2為什麼 L3出問題怎麼辦。數值為常見量級,實際以面板與 IC 規格書為準。

E01 面板與 TFT 基礎

L1是什麼

名詞意思
a-Si TFT非晶矽背板。遷移率約 0.5～1 cm²/V·s,製程步驟少、大面積便宜,大尺寸 LCD(TV、監視器)主流
LTPS TFT低溫多晶矽。遷移率約 50～100 以上,可把部分驅動電路做在玻璃上,用於高 PPI 手機 LCD 與 AMOLED
Oxide(IGZO)TFT氧化物半導體。遷移率約 10～30,關態漏電極低,用於平板、筆電、大尺寸 OLED TV
LTPO同一片背板混用 LTPS(驅動)與 Oxide(開關),兼顧驅動力與低漏電,讓手機能降到 1 Hz 刷新
LCD 畫素1 顆 TFT 當開關＋液晶電容 Clc＋儲存電容 Cst(1T1C),電壓決定液晶轉多少、透多少光
AMOLED 畫素最少 2T1C:開關 TFT 把電壓寫進電容,驅動 TFT 依電壓供電流讓 OLED 發光;量產常見 6T1C、7T1C(含補償)
LCD vs OLEDLCD = 背光＋液晶光閥＋彩色濾光片;OLED = 每個子畫素自己發光,不需背光與液晶

L2為什麼

  • 為什麼 AMOLED 不用 a-Si?OLED 是電流驅動,亮度跟驅動 TFT 的電流成正比。a-Si 遷移率低、要很大的 TFT 才推得動,而且長時間偏壓下臨界電壓(Vth)會漂移,電流跟著變,亮度就不均。
  • 為什麼 Oxide 能低頻刷新?關態漏電極低,畫素電容的電壓在一幀內幾乎不掉,刷新率降到很低也不閃,省下驅動功耗。
  • 為什麼 OLED 要補償電路?每顆驅動 TFT 的 Vth、遷移率都有些微差異,OLED 材料又會隨使用老化,不補償就出現 mura 與烙印。補償分內部(畫素電路先抵銷 Vth)與外部(量測後由 driver 改資料)。
  • 為什麼 OLED 黑得徹底?黑就是不發光;LCD 的背光一直亮,液晶關不死會漏一點光,對比因此受限。

L3出問題怎麼辦

現象最可能原因對策
AMOLED 用半年後固定 UI 位置留下殘影、局部變暗OLED 材料老化不均(烙印),加上驅動 TFT Vth 漂移外部補償(依累積使用量修資料)、畫面像素位移、降低靜態元素亮度
LCD 顯示靜止畫面一段時間後出現殘影液晶內離子被直流成分吸附;常因 VCOM 偏離中心,正負極性電壓不對稱重調 VCOM(flicker 最小點)、確認極性反轉正常
LTPO 手機低刷新時輕微閃爍保持時間拉長,畫素電壓因漏電下降,亮度在一幀內變化開關 TFT 用 Oxide 降漏電、低頻時調補償或插入自刷新
單一亮點或暗點單顆 TFT 或畫素電極失效雷射修補成暗點,或依缺陷規格判等級
E02 Driver IC 架構

L1是什麼

名詞意思
Source driver把一列的數位灰階轉成類比電壓,送到每條 data line。內部依序是移位暫存器／latch → level shifter → DAC → output buffer
Gate driver一次把一條 gate line 拉到 VGH(TFT 打開),其餘維持 VGL(關),逐列掃描。做在玻璃上叫 GOA／GIP
Gamma灰階碼到輸出電壓的非線性對照;由幾個 gamma 參考電壓(綁點)加電阻分壓產生
Charge pump只用電容和開關把電壓升高或翻成負壓,產生 VGH、VGL 這類小電流的偏壓
VCOM共同電極電壓,液晶兩端的電壓以它為基準,正負極性對稱於 VCOM
TDDI觸控與顯示驅動整合在同一顆 IC,共用部分電極與時序

L2為什麼

  • 為什麼要 gamma?人眼對暗部比亮部敏感,液晶的電壓—穿透率曲線也不是直線。gamma 把電壓分配成「看起來每一階一樣亮」,否則暗部會擠成一團、出現色帶。
  • 為什麼 output buffer 的驅動力很關鍵?data line 是很大的 RC 負載,一列只有幾微秒,buffer 要在這段時間把電壓穩定到目標值,不然就是充電不足、亮度偏差。
  • 為什麼偏壓用 charge pump、主電源用電感升壓?VGH／VGL 電流小,charge pump 不需電感、省面積與成本;AVDD、OLED 的 ELVDD 這類大電流就要電感式 boost,效率才夠。
  • 為什麼要兩組 gamma?極性反轉時正、負極性各要一套對 VCOM 對稱的電壓,source driver 依目前極性選用。

L3出問題怎麼辦

現象最可能原因對策
畫面出現幾條垂直帶狀的亮度差(block mura)多顆 source driver 之間 gamma 或輸出 offset 不一致逐顆校正 gamma、匹配 offset,或改用單顆／同批 IC
漸層出現一條條色帶gamma 綁點設定不當,或位元深度不足重調 gamma 曲線、開 FRC／dithering
高解析、高刷新率版本畫面偏暗或串擾一列時間變短,buffer 來不及把 data line 充到位預充電(pre-charge)、加強 buffer 驅動力、降低走線負載
開機瞬間閃一下亂畫面電源上電順序錯,VGH／VGL／AVDD 還沒穩就開始送資料照規格書的 power sequence 調整上電與 reset 時序
VGH 在高溫或重負載時掉壓charge pump 飛電容太小或負載電流超出能力加大電容、減少級數損失,或改用電感式升壓
E03 面板介面規格

L1是什麼

名詞意思
MIPI DSI手機面板主流。實體層 D-PHY:1 對時脈 lane＋1～4 對資料 lane,高速(HS)模式傳像素,低功耗(LP)模式傳命令
Video mode／Command modeVideo mode:SoC 持續串流每一幀;Command mode:面板 IC 內有 frame buffer(GRAM),畫面變了才送

LVDS／V-by-One較早期筆電與電視常用的差動介面
SPI／I²C小尺寸低速面板可用 SPI 傳像素;更常見的是用 I²C／SPI 寫 driver IC 的暫存器(細節見 L01)

L2為什麼

  • 為什麼高速介面都用差動訊號?兩條線傳相反訊號、接收端看差值,共模雜訊互相抵銷;擺幅可以很小,省電、EMI 也低。
  • 為什麼 command mode 省電?畫面不動時 SoC 和鏈路都能休息,面板自己從 GRAM 讀出來刷新;video mode 沒有 GRAM,只要畫面在顯示就得一直傳。
  • eDP 的 PSR 為什麼省電?Panel Self Refresh:畫面靜止時 TCON 用自己的 buffer 刷新,SoC 端的顯示管線與鏈路可以關掉。
  • lane 數怎麼決定?所需頻寬 ≈ 水平總數 × 垂直總數 × 刷新率 × 每像素位元數(含 blanking 與編碼負擔),除以每 lane 速率,就知道要幾條 lane。

現象最可能原因對策

E04 時序與 TCON

L1是什麼

名詞意思
水平時序一列 = HSYNC 脈寬＋HBP(後肩)＋Hactive(有效像素)＋HFP(前肩)
垂直時序一幀 = VSYNC＋VBP＋Vactive(有效列)＋VFP
Blanking有效像素以外的時間(前後肩＋sync),不送畫面資料
Pixel clock水平總數 × 垂直總數 × 刷新率。例:1080p60 標準時序 2200 × 1125 × 60 = 148.5 MHz
DEData Enable,只在有效像素期間為高,很多面板只看 DE 不看 sync
TCON接收影像、做 overdrive／補償等處理,並產生 source 與 gate 的控制時序(啟動脈衝 STV、移位時脈 CK、輸出致能 OE、資料鎖存 LOAD 等)
GOAGate on Array:把 gate 移位暫存器直接做在面板玻璃上,TCON／level shifter 只送 STV 與多相 CK,省掉 gate driver IC 與邊框空間

L2為什麼

  • 為什麼需要 blanking?gate 要切換到下一列、source 要鎖存新資料、幀與幀之間要回到第一列,這些都需要沒有畫面資料的空檔。縮短 blanking(reduced blanking)可以降低 pixel clock。
  • 為什麼刷新率越高越難驅動?一列能用的時間 ≈ 1 ÷(刷新率 × 垂直總數)。60 Hz 改 120 Hz,每列充電時間直接減半。
  • VRR 怎麼讓刷新率可變?拉長 VFP,延後下一幀開始的時間,讓面板等顯卡出圖。
  • 為什麼 TCON 做 overdrive 要 frame buffer?要知道「上一幀是多少、這一幀要到多少」才能決定推過頭多少,所以得存上一幀。

L3出問題怎麼辦

現象最可能原因對策
畫面整體偏移,邊緣少幾行或多一條黑邊porch(HBP／VBP)參數跟面板規格不符對照面板規格書的時序表修正前後肩
畫面不同步、抖動或不亮pixel clock 超出面板允許範圍,或 sync 極性設反調回規格範圍內的 clock、改 sync 極性或改用 DE 模式
VRR 低幀率時亮度忽明忽暗一幀保持太久,畫素漏電使亮度下降低幀率補償(LFC,重複送同一幀)、改用低漏電背板
GOA 面板從某一列以下全黑gate 移位暫存器在該級斷鏈,後面收不到啟動脈衝查該級 TFT 與 CK／STV 時序,雷射修補或判不良
E05 COF／COG 製程

L1是什麼

名詞意思
COGChip on Glass:driver IC 直接壓合在面板玻璃邊緣
COFChip on Film:driver IC 壓在 polyimide 軟性薄膜上,薄膜一端接面板、一端接 PCB,可彎折到面板背面
ACF異方性導電膠:膠裡散布導電粒子,壓合後只在上下方向導通,左右不導通
BumpIC 腳位上的金凸塊,壓合時跟面板或薄膜上的 pad 夾住導電粒子
ILB／OLBInner Lead Bonding:IC 接到薄膜;Outer Lead Bonding:薄膜接到面板或 PCB
Pin mapIC 腳位、薄膜走線與面板端子三者的對應表

L2為什麼

  • 為什麼窄邊框手機偏好 COF?IC 在薄膜上,可以整片彎到面板背面,玻璃邊緣不必留放 IC 的位置。COG 便宜、步驟少,但下巴比較寬。
  • 為什麼 ACF 只上下導通?粒子濃度低,平常彼此不接觸;壓合時只有被 bump 與 pad 夾住的粒子被壓扁而導通,相鄰腳位之間仍隔著絕緣膠。
  • 為什麼 pin map 不能隨便排?單層薄膜走線不能交叉,腳位順序要配合面板端子;電源與地的腳數、走線寬度會影響壓降,高速差動對還要等長。
  • 為什麼 fine pitch 難做?間距越小,對位誤差、玻璃與薄膜熱膨脹不同造成的錯位,越容易變成開路或短路。

L1是什麼

名詞意思
電泳顯示微膠囊或微杯裡有帶正、負電的黑白(或彩色)顏料粒子,加電場把粒子拉到靠觀看面或背面,顯示黑或白
雙穩態斷電後粒子停在原位,畫面保持;只有換畫面時耗電
波形(waveform)換一次畫面不是給一個電壓,而是一串逐幀的正／零／負電壓步階,總長通常數百毫秒
LUT波形查表:依「舊灰階 → 新灰階」與溫度區間挑一段波形;由面板廠依膜片批次提供
全刷／局刷全刷(full update)整面黑白閃過再到新畫面,清得乾淨但慢;局刷(partial update)只動有變的區域,快但會累積殘影
高壓驅動source 端約 ±15 V,gate 端還要更高的正負電壓,遠高於一般 LCD;多由 PMIC 產生

L2為什麼

  • 為什麼要一串波形,不給一個電壓就好?粒子在液體裡移動慢,停在哪裡取決於累積的電場(電壓 × 時間)和出發時的位置。所以要先依舊灰階決定怎麼推,常見做法是先來回「抖動」把粒子鬆開,再推到目標灰階。
  • 為什麼波形要 DC 平衡?正負電壓對時間的積分要接近零,不然膜片裡會殘留電荷,造成殘影,長期還會損傷膜片。
  • 為什麼要溫度補償?低溫時液體黏度變高,粒子跑得慢,同一段波形推不到位,所以 LUT 依溫度分區,驅動前要先讀溫度。
  • 為什麼電子紙省電卻更新慢?雙穩態讓靜態畫面幾乎不耗電;代價是每次換畫面都要跑完整段波形,做不到 LCD 那種每秒幾十張。

現象最可能原因對策
局刷很多次之後出現鬼影局刷波形不完全 DC 平衡,殘影累積每局刷若干次插一次全刷
