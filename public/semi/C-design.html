觀念圖鑑 ／ C 設計與驗證

設計與驗證：從一行 RTL 到一張光罩

晶片設計是一連串「翻譯＋檢查」：RTL 翻成邏輯閘、邏輯閘翻成擺放好的佈局、佈局翻成光罩圖形；每翻一次就要用另一種工具確認沒翻錯（LVS／LEC）、做得出來（DRC）、跑得夠快又不出錯（STA）、電源撐得住（IR／EM）、出廠測得出來（DFT）。類比電路不走這條自動化流水線，靠人手設計、靠匹配與補償撐住精度。

對應 taxonomy C01～C05。難度標籤：L1是什麼　L2為什麼　L3出問題怎麼辦。

    一條路徑：發射端正反器（launch FF）在時脈邊緣送出資料，經過組合邏輯，到接收端正反器（capture FF）。Dmax／Dmin 是組合邏輯最長／最短路徑延遲。固定 Tcq＝0.4 ns、Tsetup＝0.3 ns、Thold＝0.2 ns。skew 為正代表接收端時脈比較晚到。

    C01數位設計流程

    一句話：前端把「功能」寫成 RTL 並翻成邏輯閘（netlist）；後端把邏輯閘擺好、接好線，做成佈局（layout）；最後用萃取＋STA確認時序、用 DRC／LVS 確認做得出來又沒接錯，才輸出 GDS 交給晶圓廠。

    L1是什麼

    名詞意思
    RTLRegister Transfer Level，用 Verilog／VHDL／SystemVerilog 描述「每個時脈暫存器之間怎麼搬資料」。寫法像程式，但描述的是硬體
    功能驗證用模擬（testbench、UVM）、lint（語法與風格檢查）、CDC（跨時脈域檢查）確認 RTL 行為對。通常是整個專案最花人力的部分
    邏輯合成（synthesis）工具把 RTL 翻成用標準元件（AND、FF…）組成的 gate-level netlist，依據時序限制（SDC）與元件庫（.lib）做最佳化
    SDCSynopsys Design Constraints：時脈頻率、輸入輸出延遲、false path、multicycle path 等時序限制。寫錯，後面所有時序結果都不可信
    LEC（等價性檢查）Logic Equivalence Check，用形式化方法證明合成前後、ECO 前後的電路功能一模一樣，不必跑模擬
    Floorplan決定晶片大小、大區塊（memory、類比 IP）位置、I/O pad 位置、電源網（power plan）
    Placement／CTS／Routing擺放標準元件 → 建時脈樹（Clock Tree Synthesis，讓時脈同時到每個 FF） → 繞金屬線。三步合稱 P&R（Place and Route）
    寄生萃取（extraction）從佈局算出每條線的電阻、電容（含線與線之間的耦合電容），輸出 SPEF 檔給 STA 用
    STAStatic Timing Analysis，不跑向量、窮舉所有路徑算延遲，檢查 setup／hold（詳見 C03）
    DRCDesign Rule Check：佈局有沒有違反晶圓廠的幾何規則（最小線寬、間距、包覆、密度、antenna）
    LVSLayout Versus Schematic：從佈局「萃取」出電路，跟 netlist 比對，找短路、斷路、元件或參數不符
    ERCElectrical Rule Check：浮接的閘極、沒接的 well、電源接錯等電氣上的錯
    GDSII／OASIS佈局的檔案格式，交給晶圓廠做光罩。交出去這件事叫 tape-out
    ECOEngineering Change Order，後段小修改。tape-out 後的 metal-only ECO 只改金屬層光罩，用預先撒好的 spare cell 改邏輯

    L2為什麼

    • DRC 過了，為什麼還要跑 LVS？DRC 只管「做得出來」，不管「對不對」：兩條線不小心碰在一起，幾何上完全合法，DRC 不會報，但電路已經短路。LVS 從佈局反推電路再跟 netlist 比，才抓得到。
    • 合成時時序過了，為什麼佈局後又不過？合成時還沒有真的線，只能用估計的線負載；擺完、繞完才知道線多長、跟誰相鄰。真正的 RC 和耦合電容出來後延遲變大，所以要以「萃取後的 STA」為準。現代流程用 physically-aware 合成，提早把擺放資訊放進來縮小落差。
    • 為什麼要 LEC，模擬不就好了？模擬只能證明「跑過的向量是對的」；LEC 用數學證明「所有輸入下都一樣」，而且比全晶片 gate-level 模擬快得多。合成、插 scan、ECO 之後都要跑。
    • 為什麼 tape-out 後偏好 metal-only ECO？全套光罩很貴，只改上面幾層金屬就能少換很多張光罩、也能用還沒做完金屬層的晶圓（wafer 先停在前段等）。代價是只能用事先撒的 spare cell，改不了大功能。
    • antenna 規則在防什麼？製程中金屬線還沒接到擴散區之前，電漿蝕刻會在長金屬線上累積電荷，透過它接著的閘極放電，打傷薄閘氧化層。規則限制「金屬面積／閘極面積」比例，違規時換到上層金屬跳線或加保護二極體。

    L3出問題怎麼辦

    現象最可能原因對策
    LVS 報 short，兩個電源網被認成同一個電源線繞錯碰在一起、或 pin／label 打錯名稱用工具的 short 定位功能找出最短的短路路徑，修佈局或修 label；VDD／VSS 的 short 要最優先修，它會掩蓋其他錯
    繞線後滿滿的 DRC 與繞不完（congestion）元件擺太密（utilization 太高）、巨集擺放擋住繞線通道、腳位集中在一角降低 utilization、調整 floorplan 讓出通道、在擁擠區加 placement blockage
    佈局後 setup 大量違規，合成時明明是正的線負載估太樂觀、SDC 沒考慮真實 I/O 延遲改 physically-aware 合成、回頭重寫 SDC、對關鍵路徑做 upsizing 或改架構（加 pipeline）
    ECO 後 LEC 不過手改 netlist 改錯、或改到 scan／clock gating 讓結構不同看 LEC 的 non-equivalent 點回推，設好 scan 模式的 constraint 再比
    tape-out 後才發現小 bug驗證漏網評估能否用 spare cell 做 metal-only ECO；不行才全光罩改版。事前在佈局撒 spare cell 就是為了這一天
    DRC 只剩金屬密度（density）違規大片空白區金屬太少，CMP 會磨出凹陷跑 metal fill（dummy 金屬）；填完要重新萃取，因為 dummy 會增加耦合電容

    C02類比與混訊

    一句話：數位只要分得出 0 和 1，類比要的是精確的電壓電流：運放負責放大與驅動、ADC／DAC 負責數位類比互轉、LDO 負責乾淨穩定的電源、band-gap 負責一個不隨溫度變的基準電壓。精度靠回授、匹配、補償撐住。

    L1是什麼

    名詞意思
    運放（op amp）高增益差動放大器，幾乎都接負回授使用。關鍵規格：開迴路增益、GBW（增益頻寬積）、相位裕度、slew rate（輸出最快變化速度）、輸入 offset、CMRR、PSRR、輸出擺幅（rail-to-rail）
    單位增益 buffer輸出直接接回反相輸入，增益 1。用途是「電壓不變、推力變大」，source driver 的輸出級就是它
    相位裕度（phase margin）迴路增益降到 1 時，相位離 −180° 還差幾度。太小會振鈴甚至震盪；dominant-pole 補償約可給到 45°，實務常再留更多
    解析度與 LSBN bit 的轉換器把滿刻度切成 2N 階，1 LSB＝滿刻度 ÷ 2N。例：10 bit、1 V 滿刻度，1 LSB 約 0.98 mV
    DNL相鄰兩階的實際間距跟理想 1 LSB 差多少。DNL＝−1 LSB 代表某一碼寬度為 0，也就是 missing code
    INL整條轉換曲線偏離理想直線最多多少 LSB，可以看成 DNL 一路累加
    單調性（monotonic）輸入變大，輸出絕不變小。DNL 優於 1 LSB 時可保證無 missing code、單調
    取樣定理取樣頻率要大於訊號頻寬的 2 倍（fs > 2B）；高於 fs/2 的成分會折回來變成假的低頻（aliasing），所以 ADC 前面要放抗混疊低通濾波器
    ADC 架構SAR（逐次逼近，中速中精度、省電，MCU 最常見）、Flash（最快、比較器數隨解析度指數增加）、Pipeline（高速）、Σ-Δ（過取樣＋雜訊整形，高精度低速，音訊與量測）
    DAC 架構電阻串（R-string，天生單調，顯示驅動 IC 的 gamma DAC 常用）、R-2R、電流舵（current steering，高速）
    LDO低壓差線性穩壓器：用一顆 pass 電晶體當可變電阻，誤差放大器比較輸出與基準，調整壓降。效率約 VOUT／VIN
    Dropout voltage還能維持穩壓的最小 VIN－VOUT。輸入再低，輸出就跟著輸入掉
    PSRR／IqPSRR：輸入電源上的漣波被擋掉多少（dB），例：1 MHz 時 55 dB，1 mV 漣波只剩約 1.8 µV。Iq：LDO 自己吃掉的靜態電流
    Band-gap reference把「隨溫度下降」的 VBE（約 −2 mV/K，CTAT）和「隨溫度上升」的 PTAT 電壓按比例相加，抵消一次溫度係數，得到約 1.2 V 的基準。一般 25～50 ppm/°C，好的設計可到 1～2 ppm/°C

    L2為什麼

    • gamma DAC 後面為什麼一定要接 buffer？電阻串的輸出阻抗高、推不動面板資料線那麼大的 RC 負載，直接接上去電壓會被拉垮、充電很慢。運放 buffer 把電壓「照抄」並提供大電流，在一條 line time 內把資料線充到位。
    • 為什麼 buffer 的 offset 會變成直條紋？每個通道一顆 buffer，製程上的元件不匹配讓每顆的 offset 都不同；同一個灰階，相鄰通道輸出差幾 mV，在面板上就是一條條亮暗不同的直線。對策是匹配佈局、加大輸入對管面積，或用 chopper／offset cancellation 讓 offset 在時間上平均掉（極性輪替）。
    • 電阻串 DAC 為什麼天生單調？每一階都是電阻串上的一個節點，碼越大節點越高，物理上不可能倒退；代價是 bit 數多時電阻與開關數量暴增，所以高 bit 數會改分段架構。
    • 運放推大電容負載為什麼容易震盪？負載電容在輸出端多加一個極點，吃掉相位裕度。對策：加大補償電容（Miller 補償，代價是頻寬與 slew rate 下降）、輸出串一顆小電阻隔離負載、或把輸出級設計成以負載電容當主極點。
    • 為什麼大壓差、大電流不適合用 LDO？LDO 是靠 pass 電晶體「吃掉」多出來的電壓，損耗功率＝(VIN－VOUT) × 負載電流，全部變成熱。壓差小或電流小時無所謂；壓差大又要大電流，效率低、晶片發燙，這時改用開關式 DC-DC（效率高但有切換漣波），需要乾淨電源時再在後面接一顆 LDO。
    • LDO 的 PSRR 為什麼高頻變差？PSRR 靠迴路增益把輸入漣波壓下去；頻率一高，誤差放大器的增益掉了，漣波就漏過去。更高頻段再靠輸出電容旁路。所以看規格書要看「在你在意的頻率」的 PSRR，不能只看 DC 值。
    • LDO 為什麼挑輸出電容？PMOS／PNP pass 元件的 LDO 輸出端是高阻抗，主極點落在輸出電容上，穩定性跟電容值與 ESR 綁在一起；有些老設計要靠 ESR 產生零點補相位，換成極低 ESR 的陶瓷電容反而震盪。規格書會給「穩定的電容值與 ESR 範圍」。
    • band-gap 為什麼需要啟動電路？它的回授結構有兩個穩態，其中一個是「所有電流都是 0」。上電時如果停在零電流狀態就永遠不會起來，所以要加 start-up 電路在上電時推一把，起來後自動退出。
    • 類比為什麼不跟著製程微縮變便宜？精度靠元件面積（越大匹配越好）與電壓擺幅，先進製程電壓更低、雜訊與匹配更難，類比面積縮不下去。這也是顯示驅動 IC 多用成熟製程、高壓製程的原因之一。

    L3出問題怎麼辦

    現象最可能原因對策
    面板出現固定位置的細直條紋（vertical line mura）source driver 通道之間 buffer offset 不一致，或 gamma 電阻串某段不匹配量各通道輸出電壓找出離群通道；設計端用 chopper／offset cancellation、匹配佈局（common-centroid、dummy 元件）
    輸出 buffer 在某些負載下振鈴、甚至震盪負載電容（面板＋COF 走線）超出設計假設，相位裕度不足模擬時把實際負載 RC 模型放進去，留足相位裕度；輸出串隔離電阻、調補償
    ADC 讀值某幾個碼永遠不出現DNL 差到 −1 LSB，出現 missing code確認規格書是否保證 no missing codes；量測用直方圖法（慢斜波或正弦輸入統計每碼出現次數）找出問題碼
    量到的頻率怪怪的，比實際訊號低很多訊號含高於 fs/2 的成分，aliasing 折回來前端加抗混疊濾波器，或提高取樣率；Σ-Δ ADC 靠過取樣放寬濾波器要求
    LDO 換了陶瓷電容後輸出震盪電容 ESR 太低，不在規格書的穩定範圍內改用規格書指定範圍的電容，或串小電阻補 ESR；新設計選「ceramic stable」的 LDO
    電池快沒電時系統亂 resetVIN 低於 VOUT＋dropout，LDO 失去穩壓、輸出跟著掉依最低輸入電壓與滿載 dropout 選料；加 UVLO 或低電壓偵測提早關機
    band-gap 電壓偶爾上電不起來start-up 電路在某些上電斜率或溫度下沒成功推動在各種 VDD 上升速度與溫度角落模擬上電；量產測試檢查上電後基準電壓

    C03時序與功耗

    一句話：時序看資料趕不趕得上（setup）、會不會太早把舊資料蓋掉（hold）；功耗看切換時的充放電（動態）與漏電（靜態）；電源網則要擔心壓降（IR drop）讓元件變慢、大電流長期沖斷導線（EM）、熱讓漏電與老化更嚴重。

    L1是什麼

    名詞意思
    Setup／Hold timeFF 取樣邊緣之前資料要穩定多久（setup）、之後還要維持多久（hold）
    Slack要求時間－實際到達時間。正＝有餘裕，負＝違規。報告常看 WNS（最差那條的 slack）與 TNS（所有負 slack 加總）
    Setup 檢查T + skew − (Tcq + Dmax) − Tsetup ≥ 0：最慢的資料要在下一個邊緣前趕到
    Hold 檢查(Tcq + Dmin) − (skew + Thold) ≥ 0：最快的資料不能在同一個邊緣就衝進接收端。式子裡沒有 T
    Clock skew／jitterskew：同一個時脈邊緣到不同 FF 的時間差（空間上）；jitter：時脈邊緣每一週期的時間抖動（時間上）
    CTSClock Tree Synthesis：用 buffer 樹把時脈平衡地送到成千上萬個 FF，壓低 skew
    PVT corner製程（快／慢）、電壓、溫度的極端組合。setup 通常看慢角落（慢製程＋低電壓，傳統上配高溫；先進製程低電壓時低溫可能更慢，見 C05 溫度反轉），hold 看快角落（快製程＋高電壓），全部角落都要過（sign-off corners）
    OCVOn-Chip Variation：同一顆晶片上不同位置的元件也有快慢差，STA 會對路徑加減一個比例（derate）保守估計
    False path／Multicycle pathfalse path：功能上永遠不會發生的路徑，不檢查；multicycle：允許花好幾個週期的路徑。都在 SDC 裡宣告
    動態功耗P = α · C · V² · f：α 切換率、C 負載電容、V 電壓、f 頻率。另有短路功耗（切換瞬間上下管同時導通）
    靜態功耗（漏電）電晶體關著也有的電流：次臨界漏電、閘極漏電、接面漏電。溫度越高、製程越先進、Vt 越低，漏電越大
    Clock gating模組閒置時把它的時脈關掉，讓 α 歸零。標準作法是 ICG cell（latch＋AND），避免關的瞬間產生毛刺
    Power gating／Multi-Vt／DVFSPower gating：整塊斷電省漏電；Multi-Vt：關鍵路徑用低 Vt（快但漏）、其他用高 Vt（慢但省）；DVFS：負載輕時同時降頻降壓
    IR drop電源網電阻上的壓降。Static：用平均電流算；Dynamic：大量元件同時切換時的瞬間電壓塌陷，現在先進設計以 dynamic 為主要風險
    Electromigration（EM）大電流密度長期推動金屬原子移動，造成空洞（斷線）或小丘（短路）。壽命用 Black 方程式估：MTTF = A · J−n · exp(Ea／kT)，n 常取 2
    熱效應功耗變成熱，接面溫度 Tj 上升 → 漏電上升 → 更熱；EM 壽命對溫度呈指數敏感。先進製程還有 FinFET 自熱（self-heating）

    L2為什麼

    • 為什麼 hold 違規降頻也救不了？hold 比的是「同一個時脈邊緣」下，新資料會不會太快到；式子裡根本沒有週期 T。所以 hold 違規的晶片在任何頻率都會錯，只能在設計時修（拉長短路徑：插 buffer／delay cell）。setup 違規則可以靠降頻「勉強能用」。可以到主圖二把 T 拉大試試。
    • skew 是好是壞？接收端時脈晚到（正 skew）等於多給資料時間，對 setup 有利、對 hold 不利；反之亦然。CTS 的目標是把 skew 壓小，進階作法（useful skew）則刻意調整 skew 去借時間給緊的路徑。
    • 為什麼降電壓最省電？動態功耗跟 V² 成正比，電壓降 10% 動態功耗約降 19%；但電壓低元件變慢，所以要配合降頻，這就是 DVFS。
    • 為什麼 clock gating 效果大？時脈網路每個週期都在切換（α＝1），而且掛滿了 FF 和 buffer，常是動態功耗的大宗。關掉閒置模組的時脈，那一整片的時脈切換和 FF 內部功耗都省掉。
    • IR drop 為什麼會變成時序問題？元件延遲隨供電電壓下降而變大。如果 STA 只用標稱電壓算，壓降大的區域實際比報告慢，晶片就在某些圖樣下偶發錯。所以 sign-off 要做 IR-aware 的時序分析，或在電壓 corner 裡預留壓降。
    • EM 為什麼電源線比訊號線危險？EM 主要怕單向直流電流；電源線電流永遠同一方向，訊號線的電流來回（AC）有部分自我修復。所以電源網、大電流輸出級（例如 source driver 輸出 buffer 的電源）要加寬線、多打 via。
    • 為什麼熱會惡性循環？漏電隨溫度上升而增加，漏電又產生更多熱；散熱不足時可能失控（thermal runaway）。COF 上的驅動 IC 散熱路徑有限，功耗與溫升是要一起算的規格。

    L3出問題怎麼辦

    現象最可能原因對策
    STA 報 setup 違規關鍵路徑邏輯太深、線太長、元件驅動力不夠upsizing、換低 Vt cell、重新擺放縮短線、插 pipeline 暫存器、改架構；最後手段是降頻
    實測只在低電壓（加高溫或低溫）時功能錯，提高電壓或降頻就好落在慢角落，關鍵路徑 setup 不夠（電壓低元件變慢）；不是 hold，因為 hold 違規降頻也不會好確認 STA 有簽到該電壓／溫度角落（含溫度反轉）；修關鍵路徑或提高規格最低電壓；量測時掃電壓與頻率畫 shmoo 圖找邊界
    STA 報 hold 違規（快角落）路徑太短，或 skew 太大在短路徑插 delay buffer；修 hold 時要同時看慢角落 setup，不要修過頭
    晶片在特定圖樣或高負載時偶發錯，降頻就好dynamic IR drop 讓局部電壓塌陷、元件變慢跑向量驅動的 dynamic IR 分析；加 decap、加強電源網、錯開大量同時切換（例如 clock gating 分時開啟）
    EM 檢查報電源線電流密度超標線太窄、via 太少，電流集中加寬線或加層、via 打雙顆以上（redundant via）、把大電流負載分散到多條電源路徑
    待機功耗比預估高很多，而且越熱越高漏電主導：用了太多低 Vt cell、沒做 power gating非關鍵路徑換高 Vt、閒置區塊 power gating；量測要在高溫角落驗證
    驅動 IC 在高溫或大畫面切換時異常總功耗（多通道 buffer 靜態電流＋充放電）讓 Tj 過高估算最壞畫面（如高頻交替圖樣）的功耗與溫升；降低 buffer 偏壓電流、改善散熱（COF 散熱片）

    C04DFT 與可測試性

    一句話：出廠時不可能把晶片所有功能都跑一遍，所以設計時就先埋好測試用的後門：把所有 FF 串成一條移位暫存器（scan chain），讓測試機可以直接灌入狀態、讀出結果；記憶體則內建自我測試（BIST）。

    L1是什麼

    名詞意思
    Scan chain把設計裡的 FF 換成 scan FF 並串起來。測試流程：shift 灌入 → capture 一拍 → shift 讀出（同時灌下一組）
    ATPGAutomatic Test Pattern Generation：工具依故障模型自動算出測試向量。有了 full scan，只要解組合邏輯問題
    Stuck-at fault假設某條線永遠卡在 0 或 1。最基本的故障模型，抓開路、短路到電源這類缺陷
    Transition fault／at-speed假設某個節點翻轉太慢，要用接近實際頻率的兩個時脈（launch、capture）測，抓延遲類缺陷。stuck-at 100% 不代表品質夠
    Bridging fault兩條相鄰訊號線短在一起
    Fault coverage／Test coverageFault coverage：抓到的故障 ÷ 全部故障；Test coverage：分母扣掉「結構上不可能測」的故障，所以數字通常比較高。看報告要先確認是哪一個
    BISTBuilt-In Self-Test：晶片自己產生測試圖樣、自己比對。MBIST 測記憶體（March 演算法依序讀寫各位址）；LBIST 測邏輯（LFSR 產生虛擬隨機圖樣、MISR 壓縮結果成 signature）
    Scan compression晶片內放解壓縮／壓縮邏輯，少數腳位驅動大量短 chain，縮短測試時間與測試機記憶體
    Boundary scan（JTAG）IEEE 1149.1：在每支 I/O 旁放 scan cell，用 TCK／TMS／TDI／TDO 測板上焊接與晶片間連線
    IDDQ量靜態電源電流，CMOS 正常時幾乎沒有，異常偏大代表有短路類缺陷
    DPPM每百萬顆出貨中的不良數。coverage 越高、逃脫（test escape）越少，DPPM 越低

    L2為什麼

    • 為什麼一定要 scan？沒有 scan，想把內部某個 FF 設成特定值，可能要從外面跑好幾千個週期；想看結果也要等它傳到腳位。scan 讓每個 FF 都「可控、可觀察」，ATPG 就只要解組合邏輯，向量數和運算時間都大幅下降。
    • 為什麼 stuck-at 夠高還要 at-speed？先進製程的缺陷很多是「變慢」而不是「卡死」（電阻性 via、細線），慢速 stuck-at 測試抓不到。transition 測試在實際頻率下 launch→capture，才看得到延遲。
    • 記憶體為什麼用 BIST 不用 scan？記憶體是密集陣列，不是 FF，不能串 scan；它的故障（相鄰格互相干擾、位址解碼錯）有專門的演算法。內建 MBIST 控制器跑 March 演算法，測試機只要下指令、讀 pass／fail，必要時還能配合備用行列做修補（repair）。
    • scan 測試為什麼比正常工作更耗電？shift 時所有 FF 一起移位，切換率遠高於正常功能（正常時很多模組被 clock gating 關掉），容易造成 IR drop 和過熱，把好片測成壞片。
    • DFT 有什麼代價？scan FF 多了 MUX（面積、延遲），多了測試腳位與測試模式邏輯；clock gating、非同步 reset 都要能在測試模式被控制。DFT 規則要從 RTL 階段就照著寫，後補很痛。

    L3出問題怎麼辦

    現象最可能原因對策
    ATPG coverage 卡在偏低有不可控的時脈或 reset（內部產生的時脈、非同步 reset）、黑盒子（類比 IP、memory 沒模型）、X 源跑 DFT rule check（DRC for test）找出違規；加 test point、測試模式下旁路內部時脈與 reset、給黑盒子加 wrapper
    Scan shift 在測試機上失敗，降低 shift 頻率就過shift 時全晶片同時切換造成 IR drop，或 scan 路徑本身有 hold 問題降低 shift 頻率、分段（分群）shift、ATPG 用 low-power fill 降低切換率
    跨時脈域的 scan chain 移位錯一位兩個時脈域之間 skew 大，造成 hold 違規chain 跨域處插 lockup latch；或依時脈域分開串 chain
    at-speed 測試把一堆好片判壞（overkill）capture 時大量切換造成 IR drop，測試條件比實際應用嚴苛；或測到功能上不會走的 false path限制 capture 切換率、在 ATPG 套用與 STA 一致的 false path／multicycle 例外
    客退品出廠測試全過test escape：故障模型沒涵蓋（延遲、bridging）、類比區塊沒測到補 transition／bridging 圖樣、加類比 BIST 或參數測試，用客退品做 failure analysis 回饋測試程式

    C05IP 與 PDK

    一句話：晶圓廠給 PDK（這個製程的模型、規則與工具設定），標準元件庫給積木（AND、FF 的時序、功耗與佈局），IP 廠給大積木（CPU、介面 PHY、記憶體）；設計公司在這些上面蓋自己的晶片，並付授權費。

    L1是什麼

    名詞意思
    PDKProcess Design Kit：SPICE 元件模型、PCell（參數化佈局）、技術檔（層定義）、DRC／LVS／萃取規則檔（rule deck）、設計規則手冊
    Design rule晶圓廠的幾何規則：最小線寬、間距、包覆（enclosure）、via 規則、金屬密度、antenna 比例。寫在 DRM（Design Rule Manual），工具版是 DRC deck
    標準元件庫預先設計好、同高度可拼接的邏輯閘。每顆有多種驅動力（X1、X2、X4）與多種 Vt 版本
    Liberty（.lib）元件庫的時序與功耗表（依輸入轉換時間與負載查表），每個 PVT corner 一份
    LEF元件或巨集的抽象佈局：外框、腳位位置、擋線區，給 P&R 工具用（不含內部細節）
    Soft IP／Hard IPSoft：RTL 原始碼，可合成到任何製程、可改；Hard：已做好的 GDS 佈局，綁特定製程，時序面積可預期但不能改。類比與 PHY 幾乎都是 hard IP
    IP 授權模式常見是一次性授權費（license fee）＋每顆出貨的權利金（royalty）。大型 IP 廠如 Arm、Synopsys、Cadence
    Silicon-proven這顆 IP 已在該製程實際下線量測過。沒有的話等於拿自己的晶片當它的測試片
    MPW（shuttle）多個客戶共用一套光罩做小量試產，攤平光罩費，常用來驗證新 IP 或新電路
    開源 PDK例：Google 與 SkyWater 的 SKY130（130 nm，Apache 2.0 授權），讓學界與個人也能做晶片

    L2為什麼

    • 為什麼設計公司離不開 PDK？晶圓廠製程參數是機密，設計端只能透過 PDK 的模型與規則「間接」知道電晶體多快、線能多細。PDK 版本一更新，模型或規則改了，模擬與簽核結果就要重跑。
    • 為什麼標準元件都同高度？同高才能像磚塊一樣排成一列列（row），上下共用電源軌（VDD／VSS rail），自動擺放工具才能大量處理。
    • 買 soft IP 還是 hard IP？soft IP 彈性大、可換製程，但時序要自己收斂、驗證責任在自己；hard IP 已經在那個製程收斂好，但換製程就要重買或重做。高速 PHY、類比、記憶體幾乎只能用 hard IP。
    • 為什麼 IP 授權費常是「授權金＋權利金」？授權金回收 IP 開發成本，權利金讓 IP 廠分享出貨量。對量大、單價低的產品（如顯示驅動 IC），權利金對毛利影響大，談判時要算清楚。
    • 為什麼同一份設計換晶圓廠不容易？元件庫、hard IP、design rule、PDK 模型都綁晶圓廠，換廠等於後端重做、類比電路重新設計與驗證。

    L3出問題怎麼辦

    現象最可能原因對策
    專案中途晶圓廠發布新版 PDK／DRC deck模型或規則修正評估差異（release note）；專案開始時鎖定版本，tape-out 前用最新 deck 再跑一次簽核，確認新規則沒有新違規
    外購 IP 整合後 DRC／LVS 報錯IP 用的 PDK 版本或金屬層數跟你的設計不同，或交付的抽象檔（LEF）與實際 GDS 不一致要求 IP 廠提供與你相同 PDK 版本、金屬堆疊的交付檔與簽核報告
    選了一顆便宜 IP，但它在這個製程沒量產紀錄不是 silicon-proven要求量測報告；先上 MPW 驗證，或改選已驗證的 IP
    低電壓、低溫時晶片比預期慢先進製程的溫度反轉（temperature inversion）：低電壓下冷反而慢，只簽了「高溫＝最慢」角落sign-off 角落補上低溫慢角落；確認元件庫有提供對應 corner 的 .lib
    antenna DRC 違規很多長金屬線直接接閘極讓 P&R 工具自動插入保護二極體，或跳到上層金屬（jumper）分段

    容易混淆

    這兩個差在哪
    DRC vs LVS做得出來嗎（幾何規則）vs 做的是你要的電路嗎（佈局與 netlist 比對）（C01）
    LVS vs LEC佈局 vs netlist（實體對邏輯）；netlist vs netlist／RTL（邏輯對邏輯）（C01）
    Setup vs Hold資料太慢（看最長路徑、可降頻救）vs 資料太快（看最短路徑、降頻救不了）（C03）
    Skew vs Jitter同一個邊緣到不同 FF 的差（空間）vs 同一個 FF 每週期邊緣的抖動（時間）（C03）
    Static vs Dynamic IR drop平均電流造成的穩態壓降 vs 大量同時切換的瞬間塌陷（C03）
    Clock gating vs Power gating關時脈、省動態功耗、狀態保留 vs 斷電源、省漏電、狀態不見要另外保存（C03）
    INL vs DNL整條曲線離直線多遠 vs 相鄰兩階間距跟 1 LSB 差多少；DNL 一路累加約等於 INL（C02）
    解析度 vs 精度切幾階（bit 數）vs 每一階準不準（INL、offset、gain error）。12 bit 的 ADC 不一定有 12 bit 的精度（看 ENOB）（C02）
    PSRR vs Line regulation輸入上交流漣波被擋多少（看頻率）vs 輸入直流電壓變化時輸出變多少（C02）
    Fault coverage vs Test coverage分母是全部故障 vs 分母扣掉不可測故障（C04）
    MBIST vs LBIST測記憶體（March 演算法）vs 測邏輯（LFSR＋MISR）（C04）
    Soft IP vs Hard IPRTL、可改可換製程 vs GDS、綁製程不能改（C05）
