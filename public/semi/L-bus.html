通訊介面與總線：晶片之間怎麼講話

每種介面都在回答同一組問題：幾條線？時脈誰給？怎麼知道從哪裡開始？怎麼知道對方收到了？答案不同，就決定了速度、腳位數、距離和抗雜訊能力。

對應 taxonomy L01～L04，另附 ISP（透過這些介面燒錄韌體，交叉 K01）。難度標籤：L1是什麼　L2為什麼　L3出問題怎麼辦。

L01I²C／SPI

一句話：I²C 用 2 條線掛很多顆，靠位址挑對象、靠 ACK 確認；SPI 用更多條線換速度，靠 CS 挑對象，不確認。

L1是什麼

名詞意思
SCL／SDAI²C 的時脈線與資料線，都是開汲極（open-drain）＋上拉電阻
速度模式Standard 100 kHz、Fast 400 kHz、Fast-mode Plus 1 MHz、High-speed 3.4 MHz（要先送 master code 才切換）。Ultra-fast 5 MHz 是推挽、單向（只能寫），跟一般 I²C 元件不相容
START／STOPSCL 為高時 SDA 由高變低是 START、由低變高是 STOP。平常 SDA 只在 SCL 為低時改變
Repeated START不送 STOP 直接再送一次 START，常用在「先寫暫存器位址、再讀資料」，中間不放掉匯流排
位址＋R/WSTART 後第一個 byte：7-bit 位址＋1 bit 讀寫（0 寫、1 讀）。10-bit 位址的第一個 byte 以保留碼 11110 開頭
ACK／NACK每個 byte 後第 9 個 clock，接收方把 SDA 拉低＝ACK；沒拉低＝NACK（沒人回應，或讀取端表示「不用再送了」）
Clock stretchingslave 還沒準備好時，把 SCL 拉住在低電位，master 要等它放開
SPI 四條線CS（片選，低有效）、SCLK、MOSI（master 出 slave 入）、MISO（master 入 slave 出）。新命名 SDO／SDI、PICO／POCI
CPOL／CPHACPOL：時脈閒置是低還是高；CPHA：在第一個還是第二個邊緣取樣。組合成 mode 0～3，兩端必須一致：mode 0（CPOL 0、CPHA 0，上升緣取樣）、mode 1（0、1，下降緣）、mode 2（1、0，下降緣）、mode 3（1、1，上升緣）
QSPI資料線擴成 4 條，同一個 clock 送 4 bit，常用於外接 Flash
I³CI²C 的後繼標準：同樣 2 線、可以和 I²C 元件共存；SCL 改推挽、最高 12.5 MHz，支援動態位址、slave 主動發中斷（in-band interrupt）與熱插入

L2為什麼

  • 為什麼 I²C 要用開汲極？很多顆共用同一條線，若用推挽，有人輸出 1、有人輸出 0 就直接短路。開汲極只會「拉低或放開」，誰拉低線就是 0，不會打架；也因此可以做 ACK、clock stretching 和多 master 仲裁。
  • 上拉電阻怎麼選？太大：上升靠電阻對匯流排電容充電，RC 太慢，高速模式的 rise time 規格過不了。太小：拉低時要吸的電流超過元件的 IOL，低電位壓不到 VOL 以下。所以最小值由 VOL／IOL 決定，最大值由 rise time 與匯流排電容決定：Rp(min) = (VDD − 0.4 V) / IOL（Standard／Fast 的 IOL 是 3 mA）；Rp(max) = tr / (0.8473 × Cb)，rise time 上限 Standard 1000 ns、Fast 300 ns、Fast-mode Plus 120 ns；匯流排電容上限 400 pF（Fast-mode Plus 550 pF）。
  • 為什麼 I²C 慢、SPI 快？I²C 的上升邊靠被動上拉，速度受 RC 限制；每 byte 還要多一個 ACK。SPI 是推挽輸出，上下都主動推，沒有協定負擔，速度只受走線和元件限制。
  • 多 master 仲裁怎麼運作？兩個 master 同時送，各自一邊送一邊讀 SDA。送 1 卻讀到 0 的那一方就知道有人在送 0，立刻退出。因為線是 wired-AND，贏家的資料完全沒被破壞。
  • SPI 沒有 ACK 怎麼確認？協定本身不確認，要靠上層：讀回 ID 暫存器、讀回剛寫的值、或 slave 自己的狀態位元／CRC。
  • SPI 為什麼腳位會爆？每多一顆 slave 就多一條 CS。腳不夠時用 daisy chain（一顆的 MISO 接下一顆的 MOSI，全部共用一條 CS）或外接解碼器。

L02UART／CAN

一句話：UART 沒有時脈線，雙方事先約好速度，靠 start bit 對齊；CAN 是差動、多節點共用的匯流排，用訊息 ID 自動仲裁，ID 越小越優先。

L1是什麼

名詞意思
UART frame閒置為高 → start bit（0）→ 5～9 個資料位元（LSB 先送）→ 可選的同位位元 → stop bit（1 或 2 個 1，部分 UART 支援 1.5）。常見寫法 8N1＝8 資料、無同位、1 stop
Baud rate每秒傳幾個 bit。常見 9600、115200。8N1 每個 byte 要 10 bit，所以 115200 baud 約每秒 11.5 KB
同位（parity）偶同位：資料加同位位元後「1」的個數是偶數。只能抓到奇數個 bit 錯
過取樣接收端用 16 倍（或 8 倍）baud 的時脈取樣，找到 start bit 的下降邊後，在每個 bit 的中間取樣
TTL／RS-232／RS-485同一種 frame，不同電氣層：TTL 是晶片電位（0／3.3 V，正邏輯）；RS-232 用 ±3～±15 V 且邏輯反相（1 是負電壓）；RS-485 差動、可多點（32 個單位負載）、低速時可拉到約 1200 m
RTS／CTS硬體流量控制：接收端快滿時拉掉 CTS，請對方暫停
CAN_H／CAN_L差動雙絞線。dominant 時 CAN_H 約 3.5 V、CAN_L 約 1.5 V；recessive 時兩條都約 2.5 V。兩端各接 120 Ω 終端電阻
dominant／recessivedominant（顯性）＝0，有人驅動；recessive（隱性）＝1，沒人驅動。只要有一個節點送 0，匯流排就是 0
仲裁大家同時送 ID，一邊送一邊聽；送 1 卻聽到 0 的退出。ID 小的（前面 0 多）勝出，而且勝方訊息不受影響
Bit stuffing連續 5 個相同位元後強制插入 1 個相反位元，讓接收端有邊緣可以重新同步
錯誤處理每個節點有發送／接收錯誤計數（TEC／REC；發送錯一次 TEC +8）。超過 127 進 error passive，TEC 超過 255 進 bus off，把壞節點踢出匯流排；之後要偵測到 128 次「11 個連續 recessive」才能恢復
CAN FD仲裁段維持原速，資料段切到更高速（最高約 8 Mbps），每個 frame 資料從 8 byte 擴到 64 byte。Classic CAN 最高 1 Mbps（線長約 40 m 內）；更新的 CAN XL 到 20 Mbps

L2為什麼

  • UART 沒有時脈，為什麼還能收對？每個 frame 都由 start bit 的下降邊重新對齊，之後只要撐 10 個 bit 不漂移太多就行。所以雙方 baud rate 的誤差兩端合計要控制在約 ±3.3% 以內（雜訊大的環境建議 ±2%）；誤差累積到最後一個 bit 取樣點偏出 bit 範圍就會錯。
  • 為什麼 RS-485、CAN 都用差動？雜訊同時打在兩條線上，接收端只看兩線的差，共模雜訊就抵消了，所以能拉得長、抗干擾。
  • 為什麼 CAN 用訊息 ID 而不是節點位址？車上是「廣播」思維：煞車訊號送出去，所有關心的節點都收。ID 同時代表優先權，重要訊息（ID 小）一定先送，延遲可預期。
  • 為什麼要 bit stuffing？CAN 沒有時脈線，接收端靠訊號邊緣重新同步。如果一直都是 0 或 1，就沒有邊緣可對齊，所以強制插入反相位元。
  • 為什麼終端電阻是 120 Ω、而且兩端都要？要等於雙絞線的特性阻抗，訊號到線尾才不會反射回來。只接一端或沒接，反射會讓邊緣振鈴、取樣錯誤。

L03USB

一句話：USB 是主機主導的匯流排：裝置插上後，主機先問「你是誰」（讀描述子），再分配位址、選設定，之後所有傳輸都由主機發起。

L1是什麼

名詞意思
速度等級Low 1.5 Mbps、Full 12 Mbps、High 480 Mbps（USB 2.0）；USB 3.2 Gen 1 5 Gbps、Gen 2 10 Gbps、Gen 2x2 20 Gbps；USB4 40 Gbps。時脈精度要求：Full ±2500 ppm、High ±500 ppm
描述子（descriptor）裝置的自我介紹，階層是 Device → Configuration → Interface → Endpoint，另有 String 描述子放文字
VID／PIDDevice 描述子裡的廠商 ID 與產品 ID，主機靠它找驅動程式
端點（endpoint）裝置上的資料緩衝區，有編號與方向（IN 進主機、OUT 出主機）。端點 0 固定用於控制
四種傳輸Control：設定與查詢；Bulk：大量資料、保證正確、不保證時間（隨身碟）；Interrupt：少量、定期輪詢（鍵盤滑鼠）；Isochronous：保證頻寬與時間、錯了不重送（音訊、視訊）
列舉（enumeration）見上圖
D+／D− 上拉裝置端用 1.5 kΩ 上拉到 3.3 V：拉 D+ 表示 Full speed，拉 D− 表示 Low speed；High speed 先以 Full speed 連上，在 reset 期間另外握手（chirp）
供電VBUS 5 V；USB 2.0 列舉前只能拉 100 mA（1 個單位負載），主機讀到 Configuration 描述子裡的 bMaxPower、確認供電預算夠，Set Configuration 之後才能拉到最多 500 mA；USB 3.x 900 mA；Type-C 可宣告 1.5 A／3 A；USB PD 最高 100 W（20 V／5 A），EPR 到 240 W（48 V／5 A）
Type-C CC 腳偵測插入、正反面方向、供電能力，以及 PD 協商的通道。裝置端（sink）在 CC1、CC2 各放一顆 5.1 kΩ 下拉，電源端偵測到才開 VBUS
Class標準化的裝置類別，例如 HID（鍵盤滑鼠）、MSC（隨身碟）、CDC（虛擬序列埠）、UVC（攝影機），作業系統內建驅動

L2為什麼

  • 為什麼鍵盤用 interrupt、隨身碟用 bulk、喇叭用 isochronous？鍵盤資料少但要即時回應，所以定期問；隨身碟資料多、一個 bit 都不能錯，但慢一點沒關係；聲音晚到就沒用了，寧可掉一點也不能延遲重送。
  • 「Interrupt 傳輸」為什麼其實是輪詢？USB 裝置不能主動講話，所有傳輸都由主機發起。interrupt 傳輸是主機保證「每隔固定時間來問一次」。
  • 為什麼一開始要用位址 0？剛插上的裝置還沒有位址，主機一次只 reset 一個埠，所以那一刻用位址 0 跟它講話不會撞到別人，問完再分配正式位址。
  • USB 2.0 怎麼在沒有時脈線下收對？D+／D− 用 NRZI 編碼（0 代表電位翻轉、1 代表不變），接收端靠翻轉重新鎖時脈；連續 6 個 1 就沒有翻轉，所以發送端強制插入一個 0（bit stuffing）。道理跟 CAN 的 bit stuffing 一樣。
  • 為什麼做 USB 轉 UART（CDC）很方便？CDC 是標準 class，作業系統內建驅動，插上就是一個 COM port，不用另外安裝。

名詞意思
lane一組發送差動對＋一組接收差動對，全雙工。x1、x4、x8、x16 是 lane 數
三層Transaction 層（TLP：讀寫請求與資料）、Data Link 層（DLLP：ACK／NAK、流量控制、重送）、Physical 層（編碼、序列化、電氣）
Link training（LTSSM）上電後兩端自動協商的狀態機：Detect（偵測對方的接收端）→ Polling（位元鎖定、極性）→ Configuration（決定 lane 寬度與順序）→ L0（正常傳輸）；出錯時進 Recovery，Gen3 起在這裡做等化（equalization）
眼圖（eye diagram）把很多個 bit 疊在一起看。眼高是電壓方向的餘裕（雜訊、損耗吃掉它）；眼寬是時間方向的餘裕（抖動吃掉它）。張得越開越穩
AC 耦合電容每條 TX 差動線上串一顆電容（約 75～265 nF），隔掉直流，讓兩端可以各自設定自己的共模偏壓；Detect 階段也靠它偵測對方的接收端
Retimer／Redriver走線太長時放大訊號：redriver 只放大，retimer 會重新取出時脈、重送乾淨的訊號

L2為什麼

  • 為什麼從平行匯流排（PCI）改成序列（PCIe）？平行匯流排幾十條線要同時到，速度一高，每條線的長度差（skew）就讓資料對不齊。序列差動對把時脈嵌在資料裡，每條 lane 各自鎖時脈，lane 之間的偏差由接收端補償，速度才能一路往上。
  • 為什麼 Gen3 改用 128b/130b？8b/10b 每 10 bit 只有 8 bit 是資料，浪費 20%；128b/130b 只浪費約 1.5%。Gen3 傳輸率只從 5 提到 8 GT/s，實際頻寬卻接近翻倍。
  • 為什麼 Gen6 要用 PAM4？再提高 NRZ 的頻率，走線損耗太大。PAM4 一個符號用 4 個電位帶 2 bit，頻率不變、資料量加倍；代價是每個電位間距變小、對雜訊更敏感，所以配 FEC 與 FLIT 模式。
  • 為什麼會自動降速或降寬？link training 時某個速度的眼圖不夠開、或某條 lane 訓練不過，兩端就協商到較低的速度或較少的 lane，讓系統還能動，但效能掉了。

L3出問題怎麼辦

現象最可能原因對策
x16 的卡只跑在 x8 或 Gen3某幾條 lane 訓練失敗（接觸、走線損傷）、插槽本身只有 x8 電氣、BIOS 設定查 link status、換插槽、檢查 BIOS；量測失敗 lane 的訊號品質
高速時 correctable error 很多、偶發掉卡訊號完整性不足：插入損耗、反射、串擾、參考時脈抖動縮短走線、改低損耗板材、加 retimer、調整等化參數、檢查參考時脈
眼圖閉合走線太長、via stub 反射、阻抗不連續背鑽 via stub、維持差動阻抗連續、AC 耦合電容位置最佳化
LTSSM 卡在 Detect，主機抓不到裝置TX 端少了 AC 耦合電容、對端沒上電，或 PERST#／參考時脈時序不對確認耦合電容（約 75～265 nF）、檢查 PERST# 放開與 REFCLK
Gen4 正常，Gen5 不穩Nyquist 頻率從 8 GHz 變 16 GHz，損耗大增；通道總損耗預算 Gen4 約 28 dB、Gen5 約 36 dB重算損耗預算，超過就加 retimer 或改低損耗板材

K01×LISP：透過這些介面燒錄韌體

一句話：ISP（In-System Programming）是晶片已經焊在板子上，透過 UART、I²C、SPI、USB 或 SWD／JTAG 把韌體寫進去，不用拆下來放燒錄器。

L1是什麼

名詞意思
ISP在板上燒錄。常見做法是晶片內建一段 ROM bootloader，開機時依 BOOT 腳位或特定指令進入燒錄模式，從 UART／I²C／USB 接收新韌體
IAP（In-Application Programming）由使用者自己的程式（自寫的 bootloader）在執行中接收新韌體、寫進 Flash，例如 OTA 更新
SWD／JTAG除錯介面，也能直接寫 Flash，不需要晶片裡的 bootloader
進入方式BOOT 腳位在 reset 時的電位、特定 UART 同步字元、I²C 指令、或主程式收到更新命令後跳進 bootloader

L2為什麼

  • ISP 和 IAP 差在哪？ISP 用的是晶片廠內建、不會被改掉的 ROM bootloader，所以就算 Flash 全空也救得回來；IAP 用自己的 bootloader，彈性大（可以加密、走任何介面、做 OTA），但它本身壞了就只能靠 ISP 或 SWD 救。
  • 顯示驅動 IC、PMIC 為什麼常用 I²C 更新？這些 IC 本來就透過 I²C 讓主機寫設定（gamma、VCOM、時序），沿用同一條線燒錄韌體或 OTP／MTP，不用多拉腳位。
  • 為什麼要防磚？燒到一半斷電，Flash 裡就是半新半舊的韌體，開機跑不起來。常見作法：雙 bank（新韌體寫到另一半，驗證 CRC／簽章後才切換）、保留不可覆寫的 bootloader、開機失敗自動回退（fallback）。

L3出問題怎麼辦

現象最可能原因對策
UART ISP 一直連不上沒進到燒錄模式（BOOT 腳位電位或 reset 時序不對）、baud 自動偵測失敗、TX／RX 接反確認 reset 時 BOOT 腳位的電位、照規格書送同步字元（例：STM32 送 0x7F、回 0x79 是 ACK，而且要用偶同位 8E1）、降 baud 再試
OTA 更新到一半斷電，裝置變磚單一 bank 直接覆寫，沒有回退機制改雙 bank＋CRC／簽章驗證後才切換；保留 ROM ISP 路徑當最後救援
I²C 燒錄偶發失敗、寫進去的資料驗證不過寫 Flash 期間 IC 會 clock stretching 或暫時不回 ACK，主機沒等就送下一筆照規格書的寫入等待時間或輪詢狀態位元，支援 clock stretching，每塊寫完讀回比對
燒錄完 SWD 再也連不上韌體把 SWD 腳改成 GPIO、進入低功耗，或開啟了讀保護拉 BOOT 腳進 ROM bootloader 重燒，或用除錯器的「reset 時連線」模式；讀保護解除通常會整片清除
SWD 永久連不上，怎樣都解不開讀保護設到最高等級（例：STM32 RDP Level 2），永久關閉除錯介面不可逆。量產前確認 option byte 設定，開發板不要設最高等級

容易混淆

這兩個差在哪
7-bit vs 8-bit I²C 位址7-bit 是真正的位址；8-bit 寫法是把 R/W 也算進去（左移一位）。0x50 的 7-bit 位址，8-bit 寫成 0xA0／0xA1
NACK 的兩種意思寫入時：沒人回應或對方拒收；讀取時：master 用 NACK 告訴 slave「最後一個 byte，不用再送了」
CPOL vs CPHA時脈閒置電位 vs 在第幾個邊緣取樣（L01）
Baud rate vs bit rate每秒幾個符號 vs 每秒幾個 bit。UART、CAN 一個符號一個 bit，兩者相同；PAM4 一個符號 2 bit
dominant vs recessive0、有人驅動、會贏 vs 1、沒人驅動、會被蓋掉（L02）
Bulk vs Isochronous保證正確、不保證時間 vs 保證時間、不保證正確（L03）
GT/s vs GB/s每秒傳幾次「transfer」（每 lane 的原始位元率）vs 扣掉編碼後實際每秒幾個 byte。Gen6 用 PAM4，64 GT/s 的符號率其實是 32 GBaud（每個符號 2 bit）（L04）
ISP vs IAP晶片內建 bootloader 燒錄 vs 自己的程式在執行中更新（ISP 段）
RS-232 vs TTL UART同樣的 frame；RS-232 是正負電壓且邏輯反相，直接接 MCU 腳會燒（L02）
