觀念圖鑑 ／ M 數位邏輯與 FPGA 驗證

數位邏輯與 FPGA 驗證：每個 flip-flop 都只在時脈邊緣看一眼

同步數位電路的整套規矩，都建立在一個假設上：資料在時脈邊緣前後那一小段時間（setup／hold 視窗）裡保持不動。組合邏輯要在一個週期內算完（時序收斂）、不同時脈之間要靠同步器交接（CDC）、RTL 要寫成合成器看得懂的樣子、驗證要證明這些假設真的成立。大部分「模擬會過、上板就壞」的問題，都是這個假設在某處被打破。

對應 taxonomy M01～M05。難度標籤：L1是什麼　L2為什麼　L3出問題怎麼辦。

主圖：一個訊號跨時脈時，到底發生什麼事

圖例：斜線區＝亞穩態（電壓停在 0 與 1 之間，多久才落定是機率問題）；虛線框＝clk_b 上升緣的 setup／hold 視窗；淡灰直線＝clk_b 的取樣邊緣。

跨時脈訊號怎麼過：一張表選方法

要過去的是什麼用什麼關鍵條件常見誤用
單 bit、慢變的準位（enable、模式設定）雙級（或三級）同步器來源端訊號要穩定得比目的端週期久同一個訊號在目的端同步兩次，分給兩個模組 → 兩邊可能差一拍
單 bit 脈衝，快時脈 → 慢時脈toggle 同步（脈衝轉成準位翻轉，過去後用 XOR 還原）或把脈衝拉寬來源端兩個脈衝不能靠太近單一週期的脈衝直接進雙級同步器，慢時脈根本沒取樣到
多 bit 計數器／指標（每次只加 1）先轉 Gray code 再逐 bit 同步值必須是「一次只變一格」任意跳值的資料也用 Gray（跳兩格以上就不只變一個 bit）
多 bit 資料，偶爾才換一次（暫存器設定）handshake（req／ack）或 MCP：資料先放著不動，只同步一個「資料好了」的控制訊號控制訊號同步過去之前，資料不能改每個 bit 各接一個同步器
多 bit 資料，連續一直來（視訊、封包）非同步 FIFO（dual-port RAM＋Gray 讀寫指標）深度要吃得下兩端速率差與突發量FIFO 深度只按平均速率算，沒算突發

M01數位邏輯基礎

一句話：組合邏輯只看現在的輸入；序向邏輯還會記住過去（靠 flip-flop），FSM 就是「狀態暫存器＋算下一個狀態的組合邏輯」。

L1是什麼

名詞意思
組合邏輯（combinational）輸出只由當下輸入決定，沒有記憶：AND／OR、加法器、多工器（MUX）、比較器、解碼器
序向邏輯（sequential）輸出還跟過去有關，靠 flip-flop 或 latch 記住狀態：計數器、移位暫存器、FSM
Flip-flop vs latchflip-flop 是邊緣觸發，只在時脈上升（或下降）那一刻取樣；latch 是準位觸發，enable 為高的整段時間都透明
Setup／hold time時脈邊緣之前資料要先穩定多久（setup）、之後還要保持多久（hold）。違反就可能取錯值或進入亞穩態
Clock-to-Q（tco）時脈邊緣到 flip-flop 輸出真的改變所需的時間
FSM有限狀態機：狀態暫存器＋下一狀態邏輯＋輸出邏輯
Moore vs MealyMoore：輸出只看狀態；Mealy：輸出看狀態＋輸入，所以反應早一拍，但輸入的毛刺會直接傳到輸出
狀態編碼binary（最少 flip-flop）、one-hot（每個狀態一個 flip-flop，解碼簡單、速度快，FPGA 常用）、Gray（相鄰狀態只差 1 bit）
編碼器 vs 解碼器解碼器：n 條輸入 → 2n 條中選一條為 1（位址解碼）；編碼器反過來。優先編碼器同時多條為 1 時只輸出優先權最高那條的編號（中斷控制器）
卡諾圖（K-map）把真值表排成格子，相鄰格只差 1 個變數（行列用 Gray 順序排）。把相鄰的 1 圈成 1、2、4、8 格的矩形，每一圈就是一個化簡後的乘積項；don't care（X）可以當 1 用來圈大一點
Glitch／hazard組合邏輯各路徑延遲不同，輸入變化時輸出短暫跳出錯誤脈衝。靜態 hazard 可以在卡諾圖上多圈一個「跨接」的冗餘項消除

L2為什麼

  • 為什麼同步設計都只在時脈邊緣取樣？組合邏輯輸出在變化過程中會有毛刺，只要所有毛刺在下一個邊緣前平息，flip-flop 只在邊緣「看一眼」，就完全看不到它們。這讓設計者只要管「一個週期內算不算得完」，不必管每條路徑的瞬間波形。
  • 為什麼 FPGA 常用 one-hot，ASIC 常用 binary？FPGA flip-flop 很多，邏輯是查表（LUT），one-hot 每個狀態的判斷只看一個 bit，下一狀態邏輯淺、跑得快；ASIC 面積錢多，binary 用最少暫存器。合成工具通常會自動重新編碼，可在報告裡看到它選了什麼。
  • Mealy 比 Moore 快一拍，為什麼不全部用 Mealy？Mealy 輸出是輸入經過組合邏輯直接出去，輸入有毛刺或剛好在時脈附近變化，輸出就跟著抖，而且這條組合路徑會串進下一級的時序裡。要送出晶片或跨模組的控制訊號，常改用 Moore 或把 Mealy 輸出再打一拍（registered output）。
  • 為什麼卡諾圖要用 Gray 順序排？相鄰格必須只差一個變數，圈起來時那個變數才會被消掉（A·B + A·B' = A）。照 00、01、10、11 排，01 和 10 相鄰卻差兩個變數，就圈不起來。
  • 為什麼 FSM 一定要有 default 或回到 idle 的路？binary 編碼 3 個狀態用 2 bit，有 1 個沒用到的編碼；one-hot 更多非法組合。被雜訊、亞穩態或上電初值打到非法狀態時，沒有回歸路徑就永遠卡死。高可靠設計會用合成屬性要求「safe FSM」（偵測非法狀態並回復）。

L3出問題怎麼辦

現象最可能原因對策
FSM 偶發卡死，reset 後恢復落入未定義的狀態編碼，case 沒有 default／沒有回 idle 的轉移；或外部非同步輸入沒同步就進 FSM補 default 回 idle、輸入先過同步器、需要時開 safe FSM 選項
FSM 輸出控制的訊號偶爾出現極短的毛刺輸出是組合邏輯（Mealy 或 binary 狀態解碼），解碼時多個 bit 同時變化輸出改成暫存器輸出（多打一拍或 Moore 加 one-hot）；當作時脈或非同步 reset 用的訊號一定要從 flip-flop 直接出
合成後狀態暫存器數量跟 RTL 不同合成工具自動重新編碼（例如 binary 改 one-hot）正常現象；要固定編碼時加合成屬性（例如 fsm_encoding），除錯時看合成報告的編碼對照表
同一個條件在面板端驅動（例如 TCON 的 gate 時序 FSM）偶爾晚一拍Moore 本來就晚一拍，或輸入多經過一級同步器畫出時序圖對齊；要提前就改 Mealy 再打一拍，或把判斷條件往前一個狀態
卡諾圖化簡的結果模擬對、但量到毛刺只取最少項，留下靜態 hazard同步電路裡下一級只在邊緣取樣通常不影響；若輸出直接當非同步控制，就補冗餘項或改暫存器輸出

M02Clock／Reset 與 CDC

一句話：兩個沒有固定相位關係的時脈之間，訊號遲早會落進 setup／hold 視窗，造成亞穩態；我們沒辦法消滅它，只能用同步器多給它時間落定，再用正確的結構確保多 bit 不會拆散。

L1是什麼

名詞意思
時脈域（clock domain）由同一個時脈（或同源、固定相位關係的時脈）驅動的一群 flip-flop。不同源的時脈之間就是非同步
CDCClock Domain Crossing：訊號從一個時脈域被另一個時脈域取樣
亞穩態（metastability）flip-flop 在 setup／hold 視窗內取樣到變化中的資料，輸出卡在中間電位或振盪，經過一段不確定的時間才落到 0 或 1，而且落到哪邊也不確定
雙級同步器（2-FF synchronizer）目的時脈域連續兩顆 flip-flop，中間不接任何邏輯。第一級可能亞穩態，給它一整個週期落定，第二級才拿去用。高速或高可靠時用三級
MTBF平均多久會失敗一次。同步器失敗機率隨「可用的落定時間」指數下降，常見形式為 MTBF = etr/τ ／（T0 × fclk × fdata），τ、T0 是製程與 flip-flop 的特性
同步 vs 非同步 reset同步 reset：只在時脈邊緣生效，像一般資料輸入；非同步 reset：直接接到 flip-flop 的 CLR／PRE 腳，不等時脈立刻生效
Recovery／removal非同步 reset 的「setup／hold」：reset 放開的那一刻離時脈邊緣要夠遠，否則一樣可能亞穩態
時脈閘控（clock gating）模組閒置時把時脈關掉，flip-flop 不翻轉，省動態功耗。ASIC 用整合閘控單元 ICG（latch＋AND）避免毛刺
Clock enable時脈一直在跑，只用 enable 讓 flip-flop 選擇「保持舊值」。功能等效閘控，但不碰時脈樹，FPGA 標準作法
Gray code相鄰數字只差 1 bit 的編碼，binary 轉 Gray：g = b ^ (b >> 1)
非同步 FIFO寫端、讀端各用自己的時脈，中間是 dual-port RAM；讀寫指標轉成 Gray 後跨域同步，用來判斷空／滿
ASYNC_REG（AMD／Xilinx）標在同步器 flip-flop 上的屬性：placer 會把它們放在同一個 slice 縮短走線（拉高 MTBF）、模擬時違反時序不輸出 X、可用 report_synchronizer_mtbf 報告

L2為什麼

  • 為什麼不能「消除」亞穩態，只能降低機率？flip-flop 內部是兩個反相器互鎖，取樣到中間電位時它停在不穩定的平衡點，靠雜訊推一把才倒向一邊，倒下所需時間沒有上限，只是越久越不可能。所以同步器的設計目標是 MTBF 長到遠超產品壽命，不是零。
  • 為什麼多一級同步器差那麼多？MTBF 對落定時間是指數關係，多一級等於多給一整個週期，MTBF 會乘上一個非常大的倍數。反過來，時脈頻率越高、可用時間越短、MTBF 掉得越快，所以高速設計常用三級。兩級之間走線越短越好（這就是 ASYNC_REG 要把它們放一起的原因）。
  • 為什麼多 bit 不能每個 bit 各自同步？每個 bit 的同步器各自決定「這拍看到新值還是舊值」，結果可能一半新一半舊，出現一個從來沒存在過的值（見主圖第 3 種）。Gray code 每次只變 1 bit，最壞只是晚一拍看到新值，不會看到錯值；任意資料就只能用 handshake 或 FIFO，讓資料在被取樣時保持不動。
  • 為什麼 reset 要「非同步拉起、同步放開」？拉起用非同步，時脈還沒穩、PLL 還沒鎖時也能讓電路進入已知狀態；放開若也非同步，reset 解除那一刻離時脈邊緣太近，就違反 recovery／removal，部分 flip-flop 這拍醒、部分下拍醒，FSM 一起步就錯。每個時脈域各放一個 reset 同步器。
  • 為什麼不能用 AND 閘直接閘控時脈？enable 在時脈為高時變化，AND 輸出會切出一段很窄的時脈脈衝（glitch），下游 flip-flop 可能多觸發一次。ICG 用一個在時脈低電位時透明的 latch 先鎖住 enable，保證 enable 只在時脈為低時改變。FPGA 上用 LUT 閘控時脈還會讓時脈離開專用時脈網路，skew 失控，所以用 clock enable 或專用的時脈 buffer（如 BUFGCE）。
  • 快時脈的脈衝為什麼過不去？來源端一拍寬的脈衝，可能剛好落在慢時脈兩個邊緣之間，慢時脈根本沒看到。作法是把脈衝轉成準位翻轉（toggle），過去後用前後兩拍 XOR 還原成脈衝；或回 ack 確認收到才能送下一個。
  • 顯示驅動 IC 哪裡有 CDC？主機透過 I²C／SPI 寫設定暫存器（SCL／SCLK 時脈域），內部時序電路跑在內部振盪器時脈；高速介面收資料的恢復時脈與內部 pixel／line 時脈也不同源，中間常放非同步 FIFO 或 line buffer。暫存器設定通常用「影子暫存器＋在 frame／VSYNC 邊界一次更新」，本質就是 MCP 加同步一個 load 訊號。

L3出問題怎麼辦

現象最可能原因對策
上板幾小時才偶發一次錯，模擬永遠過、換一台板子頻率不同CDC 沒同步或同步器 MTBF 不夠；RTL 模擬沒有亞穩態，看不出來跑 CDC 檢查工具（Vivado report_cdc、商用 CDC 工具）、補同步器、標 ASYNC_REG、必要時改三級

非同步 FIFO 偶爾溢位或讀到舊資料指標沒轉 Gray 就跨域、Gray 指標在跨域前經過組合邏輯（又產生毛刺）、深度不夠Gray 指標由暫存器直接輸出再進同步器；深度依突發量計算；約束用 set_max_delay -datapath_only 控制 Gray 匯流排的走線偏差

M03Verilog／RTL 撰寫

一句話：RTL 不是程式，是在描述硬體：時序區塊用 <= 描述 flip-flop、組合區塊用 = 並且每條路都要給值；寫得模擬器和合成器理解成同一個電路，才不會「模擬過、上板壞」。

① blocking（=）vs non-blocking（<=）：同樣想做兩級移位暫存器

// 錯：blocking，q1 立刻變成 d，下一行讀到的是「新的」q1
always @(posedge clk) begin
  q1 = d;
  q2 = q1;     // q2 也等於 d → 合成出來只剩一級
end

// 對：non-blocking，右邊全部先取「邊緣前的舊值」，最後一起更新
always @(posedge clk) begin
  q1 <= d;
  q2 <= q1;    // 兩級，順序對調也一樣
end

// 錯：兩個 always 用 blocking 互相讀 → 誰先執行由模擬器決定（race）
always @(posedge clk) a = b;
always @(posedge clk) b = a;   // 改成 <= 就是乾淨的交換

② 不完整的 if／case 生出 latch

// 錯：sel = 0 時 y 沒被指定 → 硬體要「記住舊值」→ 合成出 latch
always @* begin
  if (sel) y = a;
end

// 對：開頭先給預設值（或補 else）
always @* begin
  y = 1'b0;
  if (sel) y = a;
end

// 錯：case 沒列完又沒有 default，nxt 在 2'd2、2'd3 時要保持 → latch
always @* begin
  case (st)
    2'd0: nxt = 2'd1;
    2'd1: nxt = 2'd2;
  endcase
end
// 對：開頭 nxt = st;（或補 default: nxt = 2'd0;）

③ 可合成 vs 只能在 testbench 用

// 只能模擬：#延遲、時脈產生、印訊息、亂數，合成器會忽略或報錯
initial begin rst_n = 0; #100 rst_n = 1; end
always #5 clk = ~clk;
initial $display("start");

// 錯：敏感清單漏了 b → 模擬時 b 變了 y 不更新，合成卻是普通 AND 閘
always @(a) y = a & b;
// 對：always @*（SystemVerilog 用 always_comb）

// 可合成：固定次數的 for，會展開成平行的硬體（不是「跑迴圈」）
always @* begin
  cnt = 4'd0;
  for (i = 0; i < 8; i = i + 1) cnt = cnt + din[i];
end

L1是什麼

名詞意思
RTLRegister Transfer Level：描述「暫存器之間的資料怎麼在每個時脈搬動與運算」
Blocking（=）依序執行，這一行做完下一行才看得到新值。用在組合邏輯
Non-blocking（<=）同一時間步內，右邊先全部取值，最後一起更新左邊。用在時序邏輯（flip-flop）
always @(posedge clk)描述 flip-flop；加 or negedge rst_n 是非同步 reset
always @*／always_comb描述組合邏輯，自動把所有讀到的訊號放進敏感清單
always_ff／always_latchSystemVerilog 的意圖標記：工具會檢查 always_ff 裡真的是 flip-flop、always_comb 裡沒有 latch
Latch 誤生成（inferred latch）組合區塊裡某條路徑沒有給輸出值，合成器只好用 latch 保持舊值
可合成子集合成器看得懂、能對應成硬體的寫法。# 延遲、$display、fork／join、無界迴圈、浮點等只能模擬
Lint不跑模擬的靜態檢查：latch、寬度不符、未接的腳、多重驅動、敏感清單不完整（Verilator --lint-only、商用 lint）
參數化（parameter／generate）用參數控制寬度與數量，generate 依參數長出多份硬體

L2為什麼

  • 為什麼時序區塊要用 <=？真實硬體裡所有 flip-flop 在同一個邊緣「同時」取樣舊值、同時更新。non-blocking 正好模擬這件事，所以結果和寫的先後順序無關；blocking 讓前一行的新值馬上被後一行看到，結果隨順序改變，兩個 always 之間還會出現模擬器決定先後的 race。
  • 為什麼組合區塊反而用 =？組合邏輯是一層層算下去的（先算 t、再用 t 算 y），blocking 才會在同一次執行內得到最終值。組合區塊用 <= 會讓中間變數晚一個 delta 更新，模擬要多跑幾輪，敏感清單不完整時還會算錯。
  • 為什麼 latch 是壞事？不是 latch 本身有罪，而是「你沒打算要它」：它是準位觸發，時序分析難做、毛刺會穿過去，FPGA 上也沒有好的 latch 資源。看到合成報告出現 inferred latch，九成是組合區塊漏了 else／default。
  • 為什麼模擬和合成會不一致？模擬器照程式碼語意跑，合成器照「這段在描述什麼硬體」去生電路。敏感清單不完整、initial 給初值（ASIC 沒有）、# 延遲、=== 比對 X、full_case／parallel_case 這類只給合成器看的指示，都會讓兩邊看到不同電路。所以合成後要跑 gate-level 模擬或等價性檢查。
  • 為什麼 for 迴圈要小心？它不是「跑 8 次」，是「複製 8 份硬體」。迴圈裡放乘法器或大比較器，面積和時序立刻爆掉；需要依序處理的，要改成 FSM 每拍處理一筆。
  • AI 幫忙寫 RTL 要看什麼？AI 很容易寫出「軟體味」的 Verilog：組合區塊漏預設值、時序區塊用 =、把 for 當迴圈、跨時脈直接接。讓 AI 產生後，至少跑一次 lint 與合成，看 latch／多重驅動警告，再審跨時脈的每一條線。

L3出問題怎麼辦

現象最可能原因對策
RTL 模擬正確，合成後（gate-level）或上板結果不同敏感清單不完整、依賴 initial 初值、用了只給合成器的 full_case／parallel_case改 always @*／always_comb、用 reset 給初值、跑 gate-level 模擬或等價性檢查

M04FPGA 開發流程

一句話：RTL 加上約束檔，經過合成（變成 LUT／FF／BRAM／DSP）、實作（擺放與繞線）、產生 bitstream；每一步都要看報告：資源用了多少、時序 slack 是不是都 ≥ 0、約束有沒有漏。

# 約束檔（XDC，Tcl 語法）常見指令
create_clock -name clk_sys -period 10.000 [get_ports clk_in]         ;# 100 MHz
set_input_delay  -clock clk_sys 2.000 [get_ports din*]                ;# 板上外部延遲
set_output_delay -clock clk_sys 1.500 [get_ports dout*]

# 兩個不相關的時脈：告訴工具不要分析它們之間的路徑（前提：RTL 已經用同步器處理）
set_clock_groups -asynchronous -group [get_clocks clk_sys] -group [get_clocks clk_spi]

# 靜態設定暫存器：上電後就不變，不必在一個週期內到
set_false_path -from [get_cells cfg_mode_reg*]

# 多週期路徑：資料每 3 拍才用一次 → setup 放寬到 3，hold 要跟著設 N−1 = 2
set_multicycle_path 3 -setup -from [get_cells a_reg*] -to [get_cells b_reg*]
set_multicycle_path 2 -hold  -from [get_cells a_reg*] -to [get_cells b_reg*]

# Gray 指標跨域：不要整個 false path，而是限制走線延遲
set_max_delay -datapath_only 5.000 -from [get_cells wptr_gray_reg*] -to [get_cells wptr_sync1_reg*]

L1是什麼

名詞意思
合成（synthesis）RTL → 由 FPGA 基本元件組成的網表（LUT、FF、BRAM、DSP、IO）
實作（implementation）opt（最佳化）→ place（擺放）→ phys_opt（實體最佳化）→ route（繞線），最後 write_bitstream
LUT查表：把任意小型真值表存起來當組合邏輯（AMD 7 系列以後是 6 輸入）。邏輯層數＝資料經過幾個 LUT
FF／BRAM／DSPFF：flip-flop；BRAM：晶片上的區塊記憶體；DSP：硬體乘加器。合成報告的資源使用率以這幾類分列
Slack要求時間減到達時間。正的＝有餘裕；負的＝違規
WNS／TNSWorst Negative Slack：所有 setup 路徑中最差的 slack；Total Negative Slack：所有違規端點的負 slack 加總。WNS ≥ 0 才算 setup 時序收斂
WHS／THS同樣的概念換成 hold：最差 hold slack、hold 違規加總
TPWS時脈脈寬（pulse width）的違規加總，例如時脈對某元件太快
create_clock告訴工具時脈從哪裡進來、週期多少。沒有它，工具不知道要多快，等於沒做時序分析
set_input_delay／set_output_delay描述 FPGA 腳位外面那一段延遲（外部元件的 clock-to-output、板上走線），工具才能分析「從外部晶片進來」與「送到外部晶片」的 IO 路徑。沒設的 IO 埠在報告裡是 unconstrained，根本沒被檢查
False path告訴工具「這條路徑不用分析」，例如上電後不變的設定、已經用同步器處理的跨域
Multicycle path資料允許花 N 個週期才到，放寬 setup；hold 要另外調整（通常 N−1），否則 hold 檢查跟著移走變得太嚴
ILAIntegrated Logic Analyzer：燒在 FPGA 裡的邏輯分析儀，透過 JTAG 抓內部訊號波形

L2為什麼

  • WNS 和 TNS 一起看在看什麼？WNS 告訴你最糟那條差多少，TNS 告訴你壞的面有多廣。WNS −0.1 ns、TNS −0.3 ns：只有零星幾條，改那幾條或換實作策略就好；WNS −0.1 ns、TNS −500 ns：大量路徑都差一點，通常是時脈目標太激進或整體擁塞，要從架構（pipeline）或約束下手。
  • 一條違規路徑怎麼判斷該改什麼？看路徑明細的邏輯延遲與繞線延遲比例、邏輯層數、扇出。邏輯層數多 → 插 pipeline 暫存器、重寫成較淺的邏輯；繞線延遲佔大半 → 元件放太遠或扇出太大，複製高扇出暫存器、用 floorplan、降低使用率。
  • 為什麼 hold 違規通常不用自己修？hold 是資料「太快」到，router 會自動繞遠一點補延遲。繞線後還有 hold 違規，通常是時脈 skew 很大（時脈走了一般繞線、或閘控時脈）或約束錯（multicycle 只設 setup 沒設 hold）。
  • 為什麼 hold 違規降低時脈頻率也修不好？setup 比的是「資料能不能在下一個邊緣前到」，週期越長越寬鬆；hold 比的是「資料會不會在同一個邊緣剛取樣完就被新資料蓋掉」，launch 和 capture 是同一個邊緣，公式裡沒有週期這一項，只跟最短路徑延遲與時脈 skew 有關。所以只能加延遲或降低 skew，降頻沒用。
  • 為什麼不相關的時脈一定要加約束？Vivado 預設把所有時脈當成有關係的同步時脈來分析，兩個不相關時脈之間會算出一個毫無意義的極小 slack，整片紅。正確作法是 RTL 先放同步器，再用 set_clock_groups -asynchronous 或 false path 排除；Gray 指標這類多 bit 跨域則用 set_max_delay -datapath_only 限制偏差。
  • 為什麼約束寫錯比沒寫更危險？false path 範圍下太大（用萬用字元一把抓），會把真正需要分析的同步路徑也排除，報告全綠但上板壞。約束要窄、要能說出理由；每次改完看 check_timing 與 clock interaction 報告。
  • 資源使用率怎麼看？看 LUT、FF、BRAM、DSP、IO、時脈資源各自的百分比，以及跟預期差多少。使用率越接近滿，place／route 越難收斂；某類資源突然暴增或暴減，往往代表合成把東西推論成另一種資源（記憶體沒推論成 BRAM 而吃掉大量 LUT），或整塊邏輯因為輸出沒接而被最佳化掉。

L3出問題怎麼辦

現象最可能原因對策
WNS 為負，違規路徑邏輯層數很多一個週期內要做的組合運算太多插 pipeline 暫存器、把大比較器或加法器拆成多拍、用 DSP 內建暫存器
WNS 為負，違規路徑大部分是繞線延遲高扇出訊號（reset、enable）或使用率過高導致元件分散複製高扇出暫存器、reset 改同步或減少 reset 的暫存器、降低使用率、試不同實作策略

M05驗證與測試自動化

一句話：好的 testbench 是自我檢查的：自動產生激勵、自動比對參考答案、自動統計「測到哪裡」（覆蓋率），然後每次改 code 都在回歸裡重跑一遍，人只看失敗的那幾個波形。

L1是什麼

名詞意思
Testbench不會被合成的模擬環境，負責產生時脈、reset、激勵，並檢查 DUT 的輸出
DUTDesign Under Test：被測的設計
Self-checkingtestbench 自己判斷對錯並印出 PASS／FAIL，不靠人看波形
Directed vs constrained random指定測試：手寫特定情境；受限隨機：在合法範圍內隨機產生大量情境，用來撞出沒想到的角落
Assertion（SVA）寫在設計或介面上的時序規則，例如「req 拉起後 4 拍內必須有 ack」，違反就立刻報錯
Code coverage程式碼被執行到多少：line／statement、branch、condition、toggle（每個 bit 有沒有 0→1、1→0）、FSM（狀態與轉移有沒有走到）
Functional coverage驗證計畫裡列的功能情境有沒有被測到，用 covergroup／coverpoint 自己定義，例如「FIFO 滿的同時又寫入」
波形檔VCD（文字、通用、大）、FST（GTKWave 的壓縮格式）或各工具專屬格式；X＝未知、Z＝高阻抗

Verilator把 Verilog／SystemVerilog 編譯成 C++／SystemC 模型再執行的開源工具，速度快，也常拿來做 lint
回歸測試（regression）一整組測試（含不同亂數種子）每次改 code 或每晚自動重跑，比較結果有沒有退步

L2為什麼

  • 為什麼 code coverage 100% 還不代表驗完？它只證明每一行「被執行過」，不證明「結果被檢查過」，也不知道規格裡要求但程式根本沒寫的功能（漏寫的 code 不會有覆蓋率）。所以要搭配 functional coverage：先從規格列出要測的情境，再量有沒有測到。
  • 為什麼要隨機測試，又要固定種子？人想得到的情境有限，隨機能撞到兩個事件剛好同時發生這種角落；但失敗時必須能重現，所以每次執行都要把種子印進 log，失敗時用同一個種子重跑。
  • 波形裡的 X 該怎麼讀？X 通常代表沒 reset 的暫存器、多重驅動、或某個輸入沒接。X 在模擬中會傳染，但有些寫法（if 條件是 X 時走 else）會把它「吃掉」，模擬看起來正常、硬體卻是隨機值，所以 reset 後的 X 要追到源頭。
  • 零延遲 RTL 模擬看不到什麼？看不到亞穩態、時序違規、繞線延遲造成的毛刺。這些要靠 CDC 檢查、時序分析與上板（ILA）。也因此「模擬過了」只證明邏輯功能，不證明能在目標頻率下穩定跑。
  • testbench 驅動輸入為什麼常在負緣或用 <=？若 testbench 在時脈上升緣用 blocking 改輸入，DUT 在同一個時間點取樣，誰先誰後由模擬器決定（race）。在負緣驅動、或用 non-blocking／clocking block，就和真實硬體「輸入在邊緣前已穩定」一致。
  • 自動化回歸跟 Patrick 寫工具的經驗怎麼接？回歸本質是「批次跑模擬 → 解析 log → 彙整 pass／fail 與覆蓋率 → 只對失敗的保留波形」。這跟用 C# 寫批次測試 harness 判讀報告是同一件事，用 CI（Jenkins、GitLab CI 一類）或 Makefile 串起來，每次 commit 跑短回歸、每晚跑完整回歸。

容易混淆

這兩個差在哪
Flip-flop vs latch邊緣觸發，只在一瞬間取樣 vs 準位觸發，enable 為高整段透明（M01）
Moore vs Mealy輸出只看狀態、晚一拍但乾淨 vs 輸出看狀態＋輸入、早一拍但會跟著輸入抖（M01）
Setup vs hold 違規資料太慢、降頻就能解 vs 資料太快、降頻也解不了，要加延遲（M04）
亞穩態 vs 毛刺flip-flop 取樣在視窗內、輸出停在中間電位 vs 組合邏輯路徑延遲不同造成的短暫錯誤脈衝（M01、M02）
同步 reset vs 非同步 reset等時脈邊緣才生效、像資料 vs 不等時脈立刻生效，但放開時要同步（M02）
時脈閘控 vs clock enable真的把時脈關掉、省功耗但動到時脈樹 vs 時脈照跑、只讓暫存器保持，FPGA 標準作法（M02）
Gray code vs handshake只適合一次變一格的計數器／指標 vs 任意資料都行，但比較慢（M02）
Blocking vs non-blocking= 依序立即更新，用在組合 vs <= 同時取舊值最後一起更新，用在時序（M03）
False path vs multicycle path完全不分析 vs 還要分析，只是允許 N 個週期（M04）
WNS vs TNS最差那一條差多少 vs 所有違規加起來，代表範圍多廣（M04）
Code vs functional coverage程式碼有沒有被執行到（工具自動量）vs 規格情境有沒有被測到（自己定義）（M05）
RTL 模擬 vs gate-level 模擬驗邏輯功能、快 vs 驗合成後網表（可帶延遲），慢但抓得到模擬與合成不一致（M03、M05）
