程式測驗常考觀念：範例過了，隱藏測資為什麼還錯

HackerRank 這類線上測驗（OA）除了演算法，最常讓人失分的是三件事：SQL 的分組與 NULL、正規表示式比到太多或太少、邊界條件（溢位、空輸入、重複元素、差一）。範例測資通常小又乾淨，隱藏測資專門打這些地方。演算法套路見 P 章，語言細節見 H 章。

對應 taxonomy Q01～Q03。難度標籤：L1是什麼　L2為什麼　L3出問題怎麼辦。

主圖：一句 SQL 實際的執行順序

順序子句做什麼常考的後果
1FROM／JOIN把表接起來，產生所有候選列一對多 JOIN 會讓列變多，之後 SUM 會重複加
2WHERE逐列篩選還沒分組，不能用聚合函式；篩 LEFT JOIN 右表欄位會把沒配到的列也刪掉
3GROUP BY分組，每組變一列SELECT 只能放分組欄位或聚合結果
4HAVING篩「組」這裡才能寫 COUNT(*) >= 2
5SELECT算出要輸出的欄位、window function多數資料庫在 WHERE 裡看不到這裡取的別名
6ORDER BY／LIMIT排序、取前幾筆這裡可以用 SELECT 的別名

Q01SQL 查詢觀念

一句話：先想清楚每一步之後剩幾列：JOIN 決定列怎麼配對、WHERE 篩列、GROUP BY 把列壓成組、HAVING 篩組。NULL 不等於任何東西，連 NULL 都不等。

L1是什麼

名詞意思
INNER JOIN只留下兩邊都配得到的列
LEFT JOIN左表全部保留，右表沒配到的欄位填 NULL
CROSS JOIN兩表每一列兩兩配對（m × n 列）
GROUP BY相同值分成一組，每組輸出一列
WHERE vs HAVINGWHERE 在分組前篩列；HAVING 在分組後篩組，可以用聚合函式
COUNT(*) vs COUNT(col)前者數列數；後者只數 col 不是 NULL 的列
NULL 與三值邏輯和 NULL 比較的結果是 UNKNOWN，不是 TRUE；要寫 IS NULL／IS NOT NULL
window functionROW_NUMBER()、RANK()、DENSE_RANK()、SUM() OVER (PARTITION BY … ORDER BY …)：在每列旁邊算值，不把列合併
RANK vs DENSE_RANK同分時 RANK 會跳號（1, 1, 3），DENSE_RANK 不跳（1, 1, 2）

L2為什麼

  • 為什麼 LEFT JOIN 後在 WHERE 篩右表欄位，會變得像 INNER JOIN？沒配到的列右表欄位是 NULL，WHERE r.status = 'A' 對 NULL 是 UNKNOWN，這些列就被刪了。要保留就把條件寫進 ON。
  • 為什麼 NOT IN (子查詢) 會回空集合？子查詢結果只要有一個 NULL，x NOT IN (…, NULL) 對每一列都是 UNKNOWN。改用 NOT EXISTS。
  • 為什麼 JOIN 之後 SUM 變大？一對多 JOIN 讓「一」那邊的列被複製成多列，它的金額就被加了好幾次。先在子查詢聚合，再 JOIN。
  • 「第二高薪資」為什麼常用 DENSE_RANK？最高薪有兩人同分時，第二高應該是下一個不同的金額；RANK 會跳號，ROW_NUMBER 會把同分拆開。

SQL：每個部門的員工數，只列 2 人以上

SELECT d.name, COUNT(e.id) AS cnt
FROM dept d
LEFT JOIN emp e ON e.dept_id = d.id
GROUP BY d.name
HAVING COUNT(e.id) >= 2;
-- 用 COUNT(e.id)：沒有員工的部門算 0；改成 COUNT(*) 會算成 1（那一列左表還在）

L3出問題怎麼辦

現象最可能原因對策
用了 LEFT JOIN，結果還是少了沒配到的列右表條件寫在 WHERE條件移到 ON
NOT IN 查詢回空子查詢結果含 NULL改 NOT EXISTS，或子查詢加 WHERE col IS NOT NULL
JOIN 後總額比實際大一對多讓列重複先聚合再 JOIN
WHERE col = NULL 查不到任何列NULL 比較結果是 UNKNOWN改 IS NULL
沒有資料的類別在統計裡消失用了 INNER JOIN 或 COUNT(*)LEFT JOIN 加 COUNT(右表欄位)
排名題同分時答案錯RANK、DENSE_RANK、ROW_NUMBER 用錯依題意選：要不跳號用 DENSE_RANK，要唯一名次用 ROW_NUMBER

Q02正規表示式

一句話：量詞預設貪婪（能多吃就多吃），驗證格式要加錨點（^…$）才不會只比到一部分，群組會改變 findall 回傳的東西。

L1是什麼

語法意思
.任一字元（預設不含換行）；要比對真的句點寫 \.
\d \w \s數字、單字字元（字母數字底線）、空白；大寫 \D \W \S 是反面
[abc] [^abc] [a-z]字元類別：其中之一、不是其中任何一個、範圍
* + ? {m,n}前一個元素 0 次以上、1 次以上、0 或 1 次、m 到 n 次
貪婪 vs 非貪婪預設盡量多；量詞後加 ?（*?、+?）變成盡量少
^ $ \b開頭、結尾、單字邊界
( ) (?: ) |擷取群組、不擷取的群組、或

L2為什麼

  • 為什麼 <.*> 對 <a><b> 會整串比走？.* 先吃到底，再往回退到最後一個 >。要一個一個標籤就用 <.*?> 或 <[^>]*>。
  • 為什麼驗證手機號碼要加 ^ 和 $？沒有錨點時，只要字串裡「有一段」符合就算比到，abc0912345678xyz 也會過。Python 可直接用 re.fullmatch。
  • Python 的 re.match 和 re.search 差在哪？match 只從字串開頭比；search 從任何位置找第一個。
  • 為什麼 ab+ 不等於 (ab)+？量詞只作用在前一個元素：ab+ 是 a 後面一個以上的 b；(ab)+ 才是 ab 重複。
  • 為什麼有些正規表示式會跑到卡住？(a+)+$ 這種巢狀量詞遇到比不到的輸入，會嘗試指數多種切法（災難性回溯）。

Python：這段印出什麼

import re
s = "<a><b>"
print(re.findall(r"<.*>", s))                  # ['<a><b>']    貪婪
print(re.findall(r"<.*?>", s))                 # ['<a>', '<b>']
print(bool(re.match(r"\d+", "abc123")))          # False：match 只從開頭
print(bool(re.search(r"\d+", "abc123")))         # True
print(re.findall(r"(\d+)-(\d+)", "10-20 30-40")) # [('10', '20'), ('30', '40')]

L3出問題怎麼辦

現象最可能原因對策
格式驗證放過了不合法的字串沒有錨點，只比到中間一段加 ^…$ 或用 fullmatch
比對範圍比預期大很多貪婪量詞改非貪婪，或用否定字元類別 [^>]*
檔名規則把 logXtxt 也比進來. 沒跳脫寫成 \.
findall 回傳 tuple 而不是整段字串樣式裡有擷取群組不需要擷取的改 (?: )
某些輸入讓正規表示式跑很久巢狀量詞造成災難性回溯改寫成不重疊的樣式、限制輸入長度

Q03邊界條件與測資陷阱

一句話：範例測資只證明「一般情況」對；隱藏測資會丟最大值、空的、只有一個、全部一樣、剛好在邊界。寫完先用這五種在腦中跑一遍。

L1是什麼

陷阱典型樣子
整數溢位32 位元 int 上限約 21 億；n 到 105、值到 109 時，加總或相乘就會超過
空輸入與單一元素直接取 a[0]、a[n-1]，或迴圈假設至少兩個元素
重複元素用 < 還是 <=、二分搜尋要找第一個還是最後一個、去重時漏算
差一錯誤（off-by-one）迴圈上限 < n 和 <= n、區間是閉區間還是左閉右開
浮點數比較直接用 ==；輸出小數位數不符題目要求
初始值求最大值時初始值設 0，遇到全部是負數就錯

L2為什麼

  • 為什麼 long long x = a * b; 還是會溢位？右邊先用 int 算完（已經溢位），結果才轉成 long long。要先轉型再乘：1LL * a * b。
  • 為什麼二分搜尋中點寫成 l + (r - l) / 2？(l + r) / 2 在 l、r 都很大時相加會溢位。
  • 為什麼極值初始值要用第一個元素或型別極值？用 0 等於假設答案至少是 0，資料全為負數時答案就錯。
  • 為什麼重複元素特別容易出錯？很多寫法隱含「值都不同」的假設：排序後比相鄰、二分找位置、用值當 key 存索引，碰到重複就少算或覆蓋。

C++：結果是多少

int a = 100000, b = 100000;
long long bad = a * b;         // 先用 int 乘就溢位（有號溢位是 UB），再轉型已經來不及
long long ok  = 1LL * a * b;   // 10000000000

int mx = 0;                    // 資料全是負數時，答案永遠是 0：錯
int best = INT_MIN;            // 或直接用第一個元素當初始值

L3出問題怎麼辦

現象最可能原因對策
範例過了，隱藏測資答案錯（WA）且數字很大整數溢位總和、乘積改 64 位元，乘之前先轉型
某筆測資 runtime error空陣列或只有一個元素時存取越界函式開頭先處理 n = 0、n = 1
有重複值時答案多一或少一比較條件 <／<= 或二分的邊界用「全部一樣」的小測資手動跑一次
大測資逾時（TLE）複雜度不夠依 n 的上限反推需要的複雜度（見 P14）
小數答案被判錯浮點誤差或輸出位數不符照題目要求的位數輸出，比較用誤差容許
求最大值，資料全為負數時錯初始值設成 0用第一個元素或型別最小值

容易混淆

這兩個差在哪
WHERE vs HAVINGWHERE 分組前篩列、不能用聚合；HAVING 分組後篩組（Q01）
LEFT JOIN 條件寫在 ON vs WHEREON：決定怎麼配對，左表照樣全留；WHERE：配完再篩，NULL 那些列會被刪掉（Q01）
COUNT(*) vs COUNT(col)前者數列數；後者略過 NULL（Q01）
RANK vs DENSE_RANK vs ROW_NUMBER同分跳號、同分不跳號、同分也拆成不同名次（Q01）
re.match vs re.search vs re.fullmatch從開頭比、任何位置找、整串都要符合（Q02）
.* vs .*?盡量多 vs 盡量少（Q02）
閉區間 vs 左閉右開[l, r] 迴圈條件 l <= r；[l, r) 迴圈條件 l < r，兩種的更新方式不同（Q03、P03）
