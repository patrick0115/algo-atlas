H01C／C++ 核心

一句話：C／C++ 讓你直接碰記憶體，所以誰配置、誰釋放、何時失效全要自己顧；現代 C++ 的答案是 RAII：把資源綁在物件的生命週期上，離開 scope 自動釋放。違反語言規則的程式是 UB，編譯器不保證任何結果。

L1是什麼

名詞意思
指標（pointer）存「位址」的變數。可以是 nullptr、可以改指別處、可以做位址運算。*p 取值、&x 取位址
參考（reference）C++ 的別名，int& r = x;。宣告時一定要綁定、之後不能改綁、沒有「空參考」。函式參數用 const T& 可以不複製又不讓對方改
stack／heapstack：區域變數，函式結束自動釋放，空間小（數 MB 等級）。heap：new／malloc 動態配置，空間大，要 delete／free 還
new／delete vs malloc／freenew 會呼叫建構子、delete 會呼叫解構子；malloc／free 只管位元組。new[] 要配 delete[]，混用是 UB
RAIIResource Acquisition Is Initialization：建構子取得資源、解構子釋放。std::vector、std::string、std::lock_guard、std::fstream 都是
智慧指標unique_ptr：唯一擁有者，不能複製只能 move，零額外成本；shared_ptr：參考計數，最後一個放手才刪；weak_ptr：看得到但不算擁有，用來打破循環
Rule of 0／3／5類別若自己管資源，就要一起定義解構子、複製建構、複製指定（3）＋移動建構、移動指定（5）。最好的作法是 Rule of 0：成員全用 RAII 型別，五個都不用寫
Undefined behavior（UB）違反語言規則，標準不規定結果：陣列越界、解參考 null 或已釋放的指標、有號整數溢位、讀未初始化變數、資料競爭（data race）
implementation-defined／unspecified前者：各編譯器可以不同但要寫在文件（如 int 幾位元）；後者：可以不同也不必寫（如函式參數的求值順序）。兩者都不是 UB
const 正確性const int* p：不能透過 p 改值；int* const p：p 不能改指；void f() const：成員函式不改物件。constexpr：編譯期就能算出
volatile告訴編譯器「這個值可能被外部改」（硬體暫存器、ISR 共用變數），每次都要真的去讀。不是執行緒同步工具，多執行緒要用 std::atomic 或鎖

L2為什麼

  • 為什麼 RAII 比「記得 delete」安全？函式中間丟例外、提早 return、多一個分支，手動 delete 都可能被跳過。解構子在離開 scope 時一定會跑（stack unwinding），所以資源不會漏。C# 的 using、Python 的 with 是同一個想法。
  • 為什麼 UB 可怕到「Debug 正常、Release 壞掉」？編譯器被允許假設 UB 永遠不會發生，然後據此最佳化。例：return x + 1 > x; 因為有號溢位是 UB，編譯器可以直接改成 return true;；越界讀取的迴圈可能被整段改寫。最佳化等級一變，行為就變。
  • 為什麼 vector push_back 之後，之前拿的指標會失效？容量不夠時 vector 會配一塊更大的新記憶體、把元素搬過去、釋放舊的。所有舊指標、參考、iterator 都指向已釋放的地方。容量夠時只有 end() 失效。事先 reserve() 或改存索引可以避免。
  • unique_ptr 和 shared_ptr 怎麼選？預設用 unique_ptr：擁有權清楚、沒有額外成本。真的有多個擁有者才用 shared_ptr，代價是參考計數（多執行緒下是原子操作）和控制區塊；兩個物件互相 shared_ptr 會形成循環、永遠不歸零，一邊要改 weak_ptr。
  • const 正確性有什麼用？它是給編譯器檢查的契約：const T& 參數保證不改呼叫方的資料、又不用複製；const 成員函式讓物件在 const 情境下還能用。漏一個 const，往上整串呼叫鏈都得拿掉 const，所以要從一開始就加。
  • 韌體為什麼一定要 volatile？迴圈裡反覆讀狀態暫存器（例如等 SPI busy 位元清掉），沒有 volatile 時編譯器會認為「值沒被這段程式改過」而只讀一次，變成死迴圈或跳過等待。

void Work() {
    auto buf = std::make_unique<uint8_t[]>(4096); // 離開函式自動 delete[]
    std::vector<int> v{1, 2, 3};

    // *first = 9;           // UB：可能正常、可能當機、可能悄悄改到別的資料

    v[i] = 9;

L3出問題怎麼辦

現象最可能原因對策
Debug 版正常，Release 版當機或結果錯UB：讀未初始化變數、陣列越界、有號溢位，被最佳化放大開 -Wall -Wextra（MSVC /W4），用 AddressSanitizer／UBSan（-fsanitize=address,undefined）跑測試；變數宣告時就初始化
長時間執行記憶體一直漲有路徑沒 delete（例外、提早 return），或 shared_ptr 循環參考改用 unique_ptr／容器，循環的一邊改 weak_ptr；用 LeakSanitizer、Valgrind 或 Visual Studio 診斷工具抓
函式回傳的陣列一開始看起來正常，多呼叫幾個函式後內容變亂碼回傳了區域變數（stack 上）的位址：函式結束後那塊 stack 已歸還，下一個函式呼叫會重用並覆寫它，指標變成懸空不要回傳區域變數的指標或參考；改回傳 std::vector／std::array（值），或由呼叫端傳入緩衝區；開編譯器警告（回傳區域位址多半會被警告）
往 vector 加元素後，之前存的指標讀到垃圾重新配置讓指標、參考、iterator 全失效改存索引；或先 reserve() 足夠容量；迴圈中不要邊走訪邊插入
韌體等暫存器的迴圈，開最佳化後卡死或不等狀態暫存器沒宣告 volatile，讀取被最佳化掉暫存器與 ISR 共用變數宣告 volatile；多核或 RTOS 之間的同步改用 atomic／鎖
計時或計數值跑一陣子後突然變負數、邏輯錯亂有號整數溢位（UB），例如 32-bit 毫秒計數約 24.8 天就溢位改用無號型別（溢位是定義好的取模）並用差值比較 now - start >= timeout；或改用 64-bit
同一份程式換編譯器後輸出不同依賴了 unspecified 的求值順序（如 f(i++, i++)）或 implementation-defined 的型別大小拆成多行明確順序；用 <cstdint> 的 int32_t 等固定寬度型別

H02C#／.NET

一句話：.NET 的 GC 只管記憶體，檔案、handle、連線要你 Dispose；async／await 不等於開執行緒，它讓 UI 執行緒在等 I/O 時去做別的事，但你一旦用 .Result 擋住 UI 執行緒，就會自己鎖死自己。

L1是什麼

名詞意思
值型別 vs 參考型別struct、int、double、enum 是值型別：指定時複製整份，存在宣告它的地方（區域變數或物件欄位裡）。class、string、陣列是參考型別：物件在 managed heap，變數只存參考，指定時兩個變數指向同一個物件
Boxing／unboxing值型別被當成 object 或介面使用時，在 heap 上包一個物件把值複製進去（boxing，隱式）；轉回來要明確轉型（unboxing），型別不對丟 InvalidCastException，對 null 丟 NullReferenceException
GC 世代Gen 0（新）→ Gen 1（緩衝）→ Gen 2（長命）。活過一次回收就晉升一代。收 Gen 2 會連同 0、1 一起收，稱 full GC
LOHLarge Object Heap，≥ 85,000 bytes 的物件（通常是大陣列）。邏輯上隨 Gen 2 回收，預設不壓縮；可用 GCSettings.LargeObjectHeapCompactionMode 要求壓縮一次
IDisposable／usingDispose() 用來立刻釋放非受控資源（檔案、GDI 物件、序列埠、DB 連線）。using (var f = ...) { } 或 C# 8 的 using var f = ...; 保證離開 scope 時呼叫 Dispose，即使丟例外
Finalizer／SafeHandleFinalizer（~Class()）是忘了 Dispose 時的最後保險，時間不確定、會讓物件多活一輪。直接包 OS handle 時官方建議用 SafeHandle，自己不用寫 finalizer
async／await、TaskTask 代表「一個未來會完成的工作」。await 遇到未完成的 Task 就先返回，讓出目前執行緒；完成後再接著跑後半段
SynchronizationContext決定 await 之後「回哪裡跑」。WinForms／WPF 的 UI 執行緒有一個，會把後半段排回 UI 執行緒；ASP.NET Core 和 console 沒有，後半段在 thread pool 跑
ConfigureAwait(false)告訴 await「後半段不用回原來的 context」。.NET 8 起另有 ConfigureAwaitOptions（如 ForceYielding、SuppressThrowing）
async void沒有 Task 可以 await，例外直接丟到 SynchronizationContext 上、外面接不到。只該用在事件處理器（button1_Click）
LINQ 延遲執行Where、Select、OrderBy 這類回傳 IEnumerable<T> 的只是「查詢定義」，foreach 時才真的跑；ToList()、Count()、First()、Sum() 立即執行

L2為什麼

  • 為什麼 GC 要分世代？經驗法則：新物件大多很快就沒用了（暫存字串、迴圈裡的小物件）。只掃 Gen 0 這一小塊比掃整個 heap 快得多，而且通常就收得回足夠空間。活下來的才晉升，之後不必每次都重新檢查。
  • 有 GC 為什麼還要 Dispose？GC 只知道「記憶體不夠了」，不知道「檔案還鎖著」「GDI handle 快用完了」。它什麼時候跑不確定，可能幾秒後、也可能很久。檔案、序列埠、Bitmap、Font、Pen 這些包著 OS 資源的物件要你用 using 準時還。
  • await 為什麼不會卡 UI？UI 執行緒只有一條，同時負責畫面與事件。await File.ReadAllTextAsync(...) 時，UI 執行緒不是在等，而是回去處理訊息迴圈（重畫、按鈕）；I/O 完成後，後半段被排回 UI 執行緒執行，所以 await 之後可以直接改控制項。它不會自己開執行緒，CPU 重的運算要另外 Task.Run。
  • 死結的機制是什麼？見上圖。.Result 讓 UI 執行緒「坐著等」；Task 的後半段被排回 UI 執行緒，但 UI 執行緒正在坐著等，永遠輪不到。ConfigureAwait(false) 能避開，是因為後半段改在 thread pool 跑、不需要 UI 執行緒。
  • ConfigureAwait(false) 該加在哪？官方 FAQ 的原則：通用函式庫每個 await 都加（不該假設呼叫者是 UI）；應用程式碼（Form 裡）不要加，因為 await 之後你通常要碰控制項。它是保險，不是解藥，真正的解法是不要在 UI 執行緒上同步等待。
  • LINQ 延遲執行會咬人在哪？一、同一個查詢變數 foreach 兩次就執行兩次（若來源是檔案或資料庫就讀兩次）；二、結果取決於「列舉當下」的資料，定義之後再改來源，結果會變；三、例外延後到列舉時才丟，堆疊看起來跟定義的地方無關。要固定結果就 ToList() 一次。
  • struct 什麼時候比 class 好？官方設計準則：代表單一值、實例小於 16 bytes、不可變、不會常被 boxing，四項都成立才考慮 struct。否則複製成本與 boxing 反而更慢。List<Point> 裡改 list[0].X 會編譯錯誤，因為拿到的是複本。
  • boxing 為什麼慢？每次都要在 heap 配一個新物件並複製值，給 GC 增加工作。舊的非泛型集合（ArrayList、Hashtable）存 int 時每筆都 boxing；用泛型 List<int> 就沒有。

H03Python 與自動化腳本

一句話：Python 寫腳本最快，但要記住三件事：GIL 讓多執行緒加速不了 CPU 運算、每個專案用自己的 venv、例外要接具體的類型並留下紀錄，否則腳本「跑完了」不代表「做對了」。

exit code腳本結束碼：0 成功、非 0 失敗。CI 或批次檔靠它判斷，sys.exit(1) 回報失敗

L2為什麼

  • 為什麼要有 GIL？CPython 用參考計數管理記憶體，每個物件的計數一直在加減。一把大鎖讓這件事不用到處加細鎖，單執行緒快、C 擴充好寫。代價是純 Python 的 CPU 運算開再多執行緒也只用到一顆核心。
  • 那為什麼 numpy 多執行緒有時會變快？很多 C 擴充在做大量運算時會主動放開 GIL，那段時間其他執行緒可以跑。I/O 也一樣：等儀器回應時 GIL 是放開的，所以多執行緒同時控制幾台儀器是有效的。
  • 為什麼每個專案都要 venv？A 專案要 pandas 1.x、B 專案要 2.x，裝在同一個全域環境一定有人壞。venv 讓依賴跟著專案走，配上鎖版本的 requirements.txt，換電腦、給同事都能重現。
  • 為什麼不要寫 except: pass？光 except: 連 KeyboardInterrupt、SystemExit 都接走，Ctrl+C 停不下來；pass 讓錯誤消失，腳本回 0、看起來成功。至少接 Exception，最好接具體類型，並且 log 下來或重新 raise。
  • 預設參數為什麼會「記住」上一次的值？預設值只在函式定義時算一次。def f(x, acc=[]) 每次呼叫共用同一個 list，越呼叫越長。慣用法是 acc=None，進函式再建新的。
  • 腳本化測試要顧什麼？測試要能自己判斷成敗（assert，而不是印出來給人看）、失敗時回非 0 exit code、呼叫外部程式時檢查回傳碼（subprocess.run(..., check=True)）、每次從乾淨狀態開始（fixture）。

H04物件導向設計

一句話：物件導向的目的不是「用很多 class」，而是讓改一個地方不會牽動一大片：把會變的東西藏在介面後面（封裝＋多型），能用「組合」就不要用「繼承」。

L1是什麼

名詞意思
封裝把資料和操作它的方法包在一起，外面只能透過公開方法改，內部規則（如「電壓不能超過上限」）不會被繞過
繼承子類別沿用父類別的成員並擴充。「is-a」關係
多型同一個呼叫，依實際物件型別跑不同實作（C# virtual／override、介面；C++ virtual；Python 鴨子型別）
組合物件「擁有」另一個物件並委派工作給它。「has-a」關係
介面 vs 抽象類別介面：只定契約，一個類別可實作多個；C# 8 起可帶預設實作，但不能有實例欄位。抽象類別：可以有欄位、建構子與部分實作，只能單一繼承
S：單一職責一個類別只有一個「改變的理由」
O：開放封閉對擴充開放、對修改封閉：加新功能靠新增類別，不改舊程式
L：Liskov 替換任何用父類別的地方換成子類別，行為都要正確
I：介面隔離不要逼使用者依賴用不到的方法；大介面拆小
D：依賴反轉高層邏輯依賴抽象（介面），不依賴具體類別；具體物件由外部注入（DI）

L2為什麼

  • 為什麼「組合優於繼承」？繼承把子類別和父類別的內部實作綁死：父類別改一行，所有子類別都可能壞（脆弱基底類別問題），而且關係在編譯時就固定。組合只依賴對方的公開介面，執行時還能換掉（換一個輸出方式、換一種通訊介面）。
  • 介面和抽象類別怎麼選？要表達「能做什麼」（IComparable、IDisposable）、而且可能多個能力並存 → 介面。一群類別真的共用狀態和大半流程，只有少數步驟不同 → 抽象類別（template method）。不確定時先用介面，比較好改。
  • Liskov 原則在防什麼？經典反例：正方形繼承長方形，設寬度時偷偷改高度，拿長方形來算面積的程式就錯了。症狀是子類別出現 throw new NotSupportedException()，或呼叫端開始寫 if (x is Square)。
  • 依賴反轉對寫工具有什麼實際好處？可以測試。Form 裡直接 new SerialPort()、直接寫檔，就沒辦法在沒有硬體時測解析邏輯；把「通訊」「輸出」抽成介面、由外部注入，測試時塞假的實作即可。Thin Form（Form 只轉發事件）也是同一個想法。
  • Python 沒有 interface 關鍵字怎麼辦？靠鴨子型別：有那個方法就能用。要明確契約時用 abc.ABC＋@abstractmethod（忘了實作會在建立時報錯），或 typing.Protocol（給型別檢查器看的結構化介面）。

internal interface IChipLink
{
    /// <summary>寫一個暫存器。</summary>

}

{

}

{
    public List<(byte Reg, byte Value)> Log { get; } = new();
    public void Write(byte reg, byte value) => Log.Add((reg, value));
}

internal sealed class GammaWriter
{
    private readonly IChipLink _link;                  // 組合：擁有一個 link，而不是繼承它
    public GammaWriter(IChipLink link) => _link = link; // 依賴由外部注入
    public void Apply(byte[] table)
    {
        for (int i = 0; i < table.Length; i++) _link.Write((byte)i, table[i]);
    }
}

H05資料結構

一句話：選資料結構就是在選哪個操作要快：要用索引拿 → 陣列；要用 key 查 → hash；要保持排序或查範圍 → 樹；只要一直拿最小（或最大）→ heap；先進先出 → queue。

L1是什麼

結構C#／C++／Python快的操作慢的操作什麼時候用
陣列／動態陣列T[]、List<T>／std::vector／list索引存取 O(1)、尾端加入均攤 O(1)中間插入刪除 O(n)、找值 O(n)預設首選；依序處理、用索引拿
鏈結串列LinkedList<T>／std::list已拿到節點時插入刪除 O(1)索引存取 O(n)、cache 不友善很少真的比較好；LRU cache 內部會用
Hash 表／集合Dictionary、HashSet／unordered_map／dict、set用 key 查、加、刪 平均 O(1)沒有順序；最壞 O(n)用名字、ID 查；去重；「有沒有出現過」
平衡樹SortedDictionary、SortedSet／std::map、std::set查、加、刪 O(log n)，保持排序比 hash 慢一個常數要按順序走訪、找範圍、找最接近的值
Heap（優先佇列）PriorityQueue<TElement,TPriority>（.NET 6 起）／std::priority_queue／heapq拿最小 O(1)、取出或加入 O(log n)找任意元素 O(n)排程、Top-K、Dijkstra
Queue／StackQueue<T>、Stack<T>／std::queue／collections.deque兩端加入取出 O(1)中間存取FIFO：生產者消費者、BFS；LIFO：復原、DFS

L2為什麼

  • 為什麼陣列實際上常常贏過理論上更好的結構？元素連續存放，CPU 一次把整條 cache line 載進來，順序走訪幾乎都命中 cache。鏈結串列每個節點散在 heap 各處，每走一步都可能 cache miss，所以就算插入是 O(1)，小到中等規模常常還是輸給 vector。
  • 動態陣列的「均攤 O(1)」是什麼意思？List<T>／vector 滿了就配一塊更大的（通常約兩倍）再整批複製，那一次是 O(n)。但容量倍增，複製越來越少發生，平均攤到每次加入還是常數。知道大概數量時先給容量（new List<T>(n)、reserve）可以省掉複製。
  • 自訂 class 當 key，為什麼「內容一樣」的新物件查不到？C# 的 class 預設 Equals／GetHashCode 比的是是不是同一個物件（參考），不是內容。兩個欄位完全相同的新物件，對 Dictionary 來說是不同的 key。要依內容比較，就兩個一起覆寫，或改用 record（編譯器自動依內容產生），或建 Dictionary 時給一個 IEqualityComparer<T>。
  • hash 什麼時候會出事？一、key 物件放進去之後被改掉，hash 值變了，再也找不到；二、自訂型別只覆寫了 Equals 沒覆寫 GetHashCode（兩者要一致）；三、多執行緒同時寫普通 Dictionary 會毀損內部結構，要用 ConcurrentDictionary 或鎖。
  • 什麼時候用樹不用 hash？需要「順序」的時候：依時間走訪事件、找某電壓以下的所有點、找最接近的 key。hash 每次要排序都得 O(n log n) 重排，樹一直保持排序。
  • heap 為什麼不乾脆排序？如果資料一直進來、每次只要拿目前最小的，排序要每次重排；heap 只維持「頂端最小」這一個性質，加入和取出都是 O(log n)。.NET 的 PriorityQueue 是陣列實作的四元 heap，優先值小的先出。
  • Python 的 list 拿來當 queue 有什麼問題？list.pop(0) 要把後面全部往前搬，是 O(n)；資料多時整個 queue 變 O(n²)。用 collections.deque 的 popleft() 才是 O(1)。

H06演算法與複雜度

一句話：Big-O 不是在算「跑幾秒」，而是在回答「資料變 2 倍、10 倍時，工作量變幾倍」。O(n) 是跟著變 2 倍；O(n²) 變 4 倍；O(log n) 只多一步。

L1是什麼

先講定義。每個名詞都給「正式定義」和「白話」兩種說法，考題用的是正式定義，理解靠白話。

名詞正式定義白話
演算法（algorithm）一組有限、明確的步驟，能把給定的輸入在有限步之內轉換成正確的輸出解一個問題的 SOP，照著做一定做得完、答案是對的
輸入規模 n衡量輸入大小的數字資料有多少：排序 100 個數 n = 100
複雜度（complexity）演算法執行所需的資源量，表示成 n 的函數資料變多時，要花的力氣漲得多快
時間複雜度執行所需的基本運算次數，表示成 n 的函數要跑多久。算的是步數不是秒數，秒數會隨電腦快慢變
空間複雜度執行所需的額外記憶體量，表示成 n 的函數要多佔多少記憶體
最好／平均／最壞情況所有大小為 n 的輸入中，步數的最小值／期望值／最大值一張張翻考卷找人：第一張就是他（1 次）、平均翻一半（n/2）、他在最後一張（n 次）。沒特別說就指最壞，因為它是保證

名詞意思
最好／平均／最壞情況同一個演算法對不同輸入的表現。Big-O 沒特別說明時通常指最壞。快速排序平均 O(n log n)、最壞 O(n²)
均攤（amortized）偶爾一次很貴、平均攤下來很便宜，例如動態陣列尾端加入

遞迴 vs 迭代遞迴：函式呼叫自己，每層佔一格 stack；迭代：用迴圈加自己管的 stack／queue。能互相改寫

L2為什麼

  • Big-O 到底怎麼「感覺」？別記公式，問一句：資料翻倍，工作量怎麼變？一筆一筆看（O(n)）→ 也翻倍；每筆跟每筆比（O(n²)）→ 變 4 倍；每一步都丟掉一半（O(log n)）→ 只多一步。所以二分搜尋在 1,000 筆是約 10 步，在 100 萬筆也才約 20 步。主圖拉桿拉到 100 萬，看 O(n²) 的長條怎麼把其他全部壓扁。
  • 怎麼從程式碼看出複雜度？一層迴圈跑 n 次 → O(n)；兩層各跑 n 次 → O(n²)；迴圈變數每次 ×2 或範圍每次砍半 → O(log n)；呼叫內建排序 → O(n log n)；小心藏起來的迴圈：List.Contains、IndexOf、list.remove、string += 本身就是 O(n)，放進迴圈就變 O(n²)。
  • 為什麼可以丟掉常數和低次項？Big-O 只在乎 n 很大時誰主導。3n² + 100n 在 n = 100 萬時，100n 只佔不到萬分之一。常數在 n 小時很重要（所以 .NET 在 16 筆以下改用插入排序），但它不會改變「翻倍時變幾倍」。
  • 為什麼排序很難比 O(n log n) 更快？只靠「兩兩比較」的排序有下限 Ω(n log n)：n 筆有 n! 種排列，每次比較最多排除一半可能，至少要 log₂(n!) ≈ n log n 次。計數排序、基數排序更快，是因為它們不靠比較，而是利用 key 的範圍（例如 0～255 的灰階值）。
  • 快速排序最壞 O(n²) 怎麼避免？每次 pivot 都挑到最大或最小（例如對已排序資料固定取第一個），分割完全不平均。函式庫的解法是隨機或三數取中選 pivot，或像 introsort 遞迴太深就切換 heap sort，把最壞壓回 O(n log n)。自己寫排序幾乎都比不上內建。
  • 時間與空間怎麼權衡？用記憶體換速度是最常見的優化：hash 索引、memoization、查表。顯示驅動 IC 裡的 gamma LUT 就是：不在每個像素即時算 gamma 曲線，而是事先把 256（或 1024）階的結果存成表，一次查表 O(1)。反過來，記憶體很緊的韌體可能寧可每次重算。
  • 遞迴和迭代怎麼選？遞迴寫樹、分治（merge sort、走訪資料夾）很自然，但每層佔 stack：Python 預設深度上限約 1000，超過丟 RecursionError；.NET 的 StackOverflowException 接不到、整個行程直接結束。C# 和 Python 都不保證尾遞迴最佳化。深度可能很大（使用者資料決定）時改成迭代＋顯式 stack。
  • 二分搜尋為什麼容易寫錯？邊界：while (lo <= hi) 還是 <、更新用 mid 還是 mid ± 1，錯一個就漏找或死迴圈。還有經典溢位：(lo + hi) / 2 在陣列超過約 10 億筆時 int 溢位，2006 年 Joshua Bloch 在 Google 部落格撰文說明，Java 函式庫的 Arrays.binarySearch（他自己寫的）就藏了這個 bug，是被人回報後才發現；寫成 lo + (hi - lo) / 2 就安全。

int bsearch_i(const int *a, int n, int target) {
    int lo = 0, hi = n - 1;
    while (lo <= hi) {
        int mid = lo + (hi - lo) / 2;      // 不寫 (lo + hi) / 2，避免溢位

        else                 hi = mid - 1; // 丟掉右半（含 mid）
    }
    return -1;
}

H07C 語言細節

一句話：C 幾乎不幫你檢查：陣列一傳進函式就退化成指標、巨集是純文字替換、有號和無號混算時有號會被轉成無號。考題多半是「這段印出什麼」，答案藏在這些隱性轉換裡。

L1是什麼

名詞意思
陣列退化（array decay）陣列名在大多數運算式裡會變成「指向第一個元素的指標」。例外：sizeof arr、&arr、用字串常值初始化陣列。函式參數寫 int a[10] 其實就是 int *a
指標運算p + 1 前進一個元素（sizeof *p 個位元組）；兩個指標相減得到元素個數。只有在同一個陣列內（含尾後一格）才有定義
struct 對齊與 padding成員要放在自己對齊要求的位址上，編譯器會在中間或尾端塞空白；整個 struct 大小是最大對齊的倍數。例：{char c; int i; char d;} 在常見平台是 12 bytes，改成 {int i; char c; char d;} 只要 8
巨集（#define）前置處理器做的文字替換，不懂型別也不管優先序。參數出現幾次就會被求值幾次
C 字串以 '\0' 結尾的 char 陣列。strlen 不含結尾，sizeof("abc") 是 4。strcpy 不檢查長度，strncpy 截斷時不保證補 '\0'
static／extern檔案層級的 static：只有這個 .c 看得到（內部連結）。函式內的 static：整個程式期間都存在、只初始化一次。extern：宣告「定義在別的檔案」
整數提升與一般算術轉換比 int 小的型別（char、short）運算前先升成 int；有號和同等級的無號混算時，有號會被轉成無號

L2為什麼

  • 為什麼在函式裡用 sizeof(a)/sizeof(a[0]) 算不出陣列長度？傳進來的已經是指標，sizeof(a) 是指標大小（常見 8），不是整個陣列。長度一定要另外傳。
  • 為什麼 -1 < sizeof(int) 是假？sizeof 的型別是無號的 size_t，-1 被轉成無號後變成極大的數。
  • 為什麼巨集要整個加括號，多行巨集要包 do { } while (0)？替換後的文字會和前後運算子結合；不包的話，接在 if 後面只有第一行受條件控制。
  • 為什麼 struct 不能直接 memcpy 到通訊封包？padding 和位元組順序（endianness）隨編譯器與平台不同，另一端解讀會錯位。
  • 為什麼函式內的 static 變數在多執行緒或 ISR 裡危險？它只有一份，所有呼叫共用，函式就不可重入（not reentrant）。

H08C++ 物件模型

一句話：多型靠每個物件裡的 vptr 指向 vtable，只有透過指標或參考呼叫才會查表；以值複製會被 slicing 切掉衍生部分。建構從基底往衍生走、解構反過來，建構期間 virtual 呼叫只會到正在建構的那一層。

L1是什麼

名詞意思
建構與解構順序建構：基底類別 → 成員（照宣告順序，不是初始化串列的順序）→ 建構子本體。解構完全相反
virtual 與 vtable類別有 virtual 函式時，每個物件多一個 vptr 指向該類別的函式表；透過基底指標或參考呼叫時，執行期查表決定呼叫哪個版本（動態繫結）
virtual 解構子要透過基底指標 delete 衍生物件，基底解構子必須是 virtual，否則是 UB（常見結果是只跑基底解構子）
object slicing把衍生物件以「值」指定或複製給基底型別，衍生的成員被切掉，之後的 virtual 呼叫也變成基底版本
move 語意右值參考 T&& 讓物件把資源「交出來」而不是複製。std::move 只是轉型，本身不搬任何東西；被移走的物件處於「有效但未指定」的狀態
複製省略（RVO）回傳區域物件時，編譯器可以直接在呼叫端建構，連 move 都省掉；C++17 起回傳暫時物件保證省略
override／finaloverride：要求編譯器確認真的覆寫到基底的 virtual；final：禁止再被覆寫或繼承

L2為什麼

  • 為什麼建構子裡呼叫 virtual 不會跑到衍生版本？基底建構子執行時，衍生部分還沒建好，物件此刻的動態型別就是基底，vptr 指向基底的 vtable。解構子裡同理。
  • 為什麼一定要寫 override？簽章只差一點（少個 const、參數型別不同）就變成一個新函式而不是覆寫，編譯不會報錯，多型悄悄失效。加了 override 編譯器會擋。
  • 為什麼 return std::move(local); 反而比較差？它把回傳值變成右值參考運算式，阻止了 RVO，原本零成本的回傳變成一次 move。
  • 為什麼多型容器要存指標？std::vector<Base> 每格只放得下 Base 的大小，放進去就 slicing；要存 std::unique_ptr<Base>。

C++：這段印出什麼

#include <iostream>
struct Base {
    Base() { hello(); }                  // 建構期間呼叫 virtual：只到 Base 版
    virtual void hello() { std::cout << "Base\n"; }
    virtual ~Base() = default;
};
struct Derived : Base {
    void hello() override { std::cout << "Derived\n"; }
};

int main() {
    Derived d;       // 印 Base
    Base b = d;      // slicing：只複製 Base 部分（複製建構子，不會再印）
    b.hello();       // Base
    Base& r = d;
    r.hello();       // Derived：參考保留多型
}

H09C++ 模板與 STL

一句話：選容器先看要不要連續記憶體、要不要排序、在哪裡插入；改動容器時要記得哪些 iterator 會失效。template 在編譯期依型別產生程式碼，所以定義要讓使用處看得到。

L1是什麼

容器／名詞重點
vector連續記憶體；隨機存取 O(1)、尾端加入均攤 O(1)、中間插入刪除 O(n)
deque兩端加入刪除 O(1)，隨機存取 O(1)，但不是一整塊連續記憶體
list雙向鏈結；已知位置插入刪除 O(1)，不能隨機存取，對 cache 不友善
map／set平衡樹（通常紅黑樹），有序，查找插入 O(log n)
unordered_map／unordered_set雜湊表，平均 O(1)、最差 O(n)，沒有順序
iterator 失效vector 重新配置時全部失效，erase 讓被刪的和之後的失效；map 的 erase 只影響被刪那個；unordered_map rehash 讓 iterator 失效
template／特化template 依型別在編譯期產生程式碼；特化是替某個型別提供專屬實作
lambda capture[=] 複製、[&] 參考、[x, &y] 逐一指定、[this] 捕捉物件指標。預設呼叫運算子是 const，值捕捉的變數要改得加 mutable

  • 為什麼中間插入也常常是 vector 比 list 快？vector 搬移的是連續記憶體，cache 命中率高；list 每個節點各配置一次，找到位置要一路追指標，實際常數很大。
  • 為什麼邊走訪邊刪要寫 it = v.erase(it)？erase 讓目前的 iterator 失效，回傳值才是下一個有效位置；寫 v.erase(it); ++it; 是對失效的 iterator 做運算。
  • 為什麼 m[key] 拿來查詢會讓 map 變大？operator[] 找不到時會插入一個預設值。只想查就用 find、count 或 C++20 的 contains。
  • 為什麼 template 的定義要放在標頭檔？編譯器要在使用處依實際型別產生程式碼，只看到宣告就產生不出來，連結時會缺符號。

L2為什麼

  • 為什麼預設值只算一次？def 是執行期的陳述式，執行時把預設值算好存在函式物件上，之後呼叫都拿同一個物件。
  • 為什麼 [[0] * 3] * 3 改一格會整欄一起變？外層的 * 3 複製的是「指向同一個內層 list 的參考」三次。要寫 [[0] * 3 for _ in range(3)]。
  • 為什麼閉包都拿到最後的值？lambda 裡的 i 是在呼叫時才查，那時迴圈已跑完。用預設參數 lambda i=i: i 在定義時把值綁住。
  • 為什麼大檔案要用 generator？一次只在記憶體放一筆，不必先建出整個 list。
  • tuple 不可變，為什麼裡面的 list 還能改？tuple 不可變的是「放哪幾個物件」，物件本身可不可變另當別論。

H11C# 語言細節

H12通用程式觀念

一句話：跨語言都會考的四件事：參數到底是傳值還是傳參考、浮點數不能直接比相等、整數有寬度和溢位、運算子有優先序和短路。看懂這四件，大部分「印出什麼」的題目就能推得出來。

L1是什麼

名詞意思
傳值 vs 傳參考傳值：函式拿到一份複本；傳參考：函式能改到呼叫端的變數（C++ &、C# ref／out）。Python、Java、C# 的參考型別是「傳物件參考的值」：改物件內容會反映回去，重新指定參數則不會
作用域 vs 生命週期作用域：名字在哪些程式碼看得到（編譯期）；生命週期：物件存在多久（執行期）。函式內的 static 變數作用域小、生命週期整個程式
浮點數精度IEEE 754 二進位浮點數無法精確表示 0.1，所以 0.1 + 0.2 == 0.3 為假；比較要用誤差容許。NaN 不等於任何值，連自己都不等
整數表示與溢位有號整數用二補數，n 位元範圍是 −2n−1～2n−1−1（32 位元約 ±21 億）。C／C++ 無號溢位是取模、有號溢位是 UB；C# 預設不檢查（繞回），checked 才丟例外；Python 整數沒有上限
短路求值&&、||（Python 的 and、or）左邊已能決定結果時，右邊不會執行
運算子優先序C 系語言中比較運算 == 比位元運算 &、| 優先，x & 1 == 0 等於 x & (1 == 0)
編譯／直譯／JITC／C++ 事先編譯成機器碼；CPython 編譯成 bytecode 再直譯執行；.NET、Java 執行時才由 JIT 編成機器碼

L2為什麼

  • 為什麼 0.1 + 0.2 不等於 0.3？1/10 在二進位是無限循環小數，只能存最接近的值；兩個近似值相加的誤差剛好讓結果和 0.3 的近似值差一點。
  • 為什麼金額不能用 double？累加誤差會讓總和差幾分錢。用整數存「分」，或用十進位型別（C# decimal、Python Decimal）。
  • 為什麼 Python 函式裡 a.append() 改得到外面，a = [...] 卻改不到？append 是改那個共用的物件；= 只是讓區域名稱 a 改貼到新物件上。
  • 為什麼 p != NULL && p->ok 的順序不能反過來？短路求值保證先確認不是 null 才解參考；反過來會先解參考空指標。
  • 為什麼 .NET 程式第一次執行某個功能特別慢？那段程式第一次被呼叫時才被 JIT 編譯，之後就是機器碼。

容易混淆

這兩個差在哪
指標 vs 參考（C++）指標可為 null、可改指、要 * 取值；參考一定綁定、不能改綁、用起來像原變數（H01）
UB vs implementation-defined前者沒有任何保證、編譯器可隨意最佳化；後者每家可以不同但要寫在文件裡、行為是確定的（H01）
volatile vs atomicvolatile：每次真的去讀（硬體暫存器）；atomic：多執行緒下不可分割且有記憶體順序保證。volatile 不能拿來做執行緒同步（H01）
Dispose vs FinalizerDispose：你主動、立刻、確定釋放；Finalizer：GC 決定何時、時間不確定、是忘了 Dispose 時的保險（H02）
async／await vs 多執行緒await 等 I/O 時不佔任何執行緒，也不會自己開新執行緒；要把 CPU 運算移出 UI 執行緒得 Task.Run（H02）
.Result vs await.Result 讓目前執行緒坐著等（UI 上會卡或死結）；await 讓出執行緒、完成後再回來（H02）
LINQ 延遲 vs 立即執行Where／Select／OrderBy 只是定義，列舉時才跑、每次列舉重跑；ToList／Count／First 當場執行（H02）
threading vs multiprocessing（Python）threading 共用一個 GIL，適合等 I/O；multiprocessing 每個行程各有 GIL，適合 CPU 運算，但資料要序列化傳遞（H03）
介面 vs 抽象類別介面：能力契約、可多個、不能有實例欄位；抽象類別：可帶狀態和部分實作、只能繼承一個（H04）
Hash vs 平衡樹hash 平均 O(1) 但沒順序；樹 O(log n) 但保持排序、能查範圍（H05）
O(log n) vs O(n log n)前者是「找一筆」（二分搜尋）；後者是「排好全部」（排序）。二分搜尋的前提是已經付過排序的成本（H06）
穩定 vs 不穩定排序相同 key 是否維持原順序。OrderBy、Python sorted 穩定；List.Sort、std::sort 不穩定（H06）
sizeof(arr) vs sizeof(p)在定義陣列那一層是整個陣列大小；傳進函式後是指標大小（H07）
巨集 vs inline 函式巨集是文字替換、參數可能重複求值、不檢查型別；inline 函式是真的函式，參數只算一次（H07）
覆寫（override）vs 隱藏（hiding）簽章完全相同的 virtual 才是覆寫；名稱相同但簽章不同會隱藏基底版本，多型不生效（H08）
std::move vs 真的搬移std::move 只是轉成右值；真正搬資源的是被呼叫到的 move 建構子或 move 指定（H08）
map[key] vs map.find(key)前者找不到會插入預設值；後者只查不改（H09）
is vs ==（Python）is 比是不是同一個物件；== 比值（H10）
淺複製 vs 深複製淺複製只複製外層，內層物件共用；深複製整棵複製（H10）
throw; vs throw ex;前者保留原堆疊；後者把堆疊起點改成目前的 catch（H11）
class vs record 的相等class 預設比參考；record 比內容（H11）
作用域 vs 生命週期作用域是名字在哪看得到；生命週期是物件活多久（H12）
