LeetCode 解題套路：看到題目先認套路，再寫程式

LeetCode 的題目千變萬化，但解法大約只有十幾種套路。真正的功夫不是背題，而是從題目的訊號認出該用哪一套：「連續子陣列」想到滑動視窗或前綴和、「已排序」想到雙指標或二分、「下一個更大」想到單調堆疊、「所有組合」想到回溯、「最多幾種／最少幾步」想到 DP 或 BFS。再用 n 的範圍反推能接受的複雜度，確認選對了。

對應 taxonomy P01～P14。難度標籤：L1是什麼　L2為什麼　L3出問題怎麼辦。程式範例用 Python（LeetCode 最常見寫法），C# 對應寫在旁邊。

P01雙指標與前綴和

一句話：雙指標是用兩個索引一起走，每一步都排除掉一個不可能的元素，把 O(n²) 的「每對都試」變成 O(n)。前綴和是先花 O(n) 存「到第 i 個為止的總和」，之後任何區間和都是 O(1) 的一次減法。

L1是什麼

名詞意思
對撞指標l 從頭、r 從尾往中間走。典型：已排序陣列找兩數和（Two Sum II）、盛最多水的容器、判斷回文
快慢指標（同向）slow 指「下一個要寫入的位置」，fast 往前掃。典型：原地刪除重複、把 0 移到最後、刪除指定值。鏈結串列找環也是這招（P06）
原地覆寫題目要求 O(1) 額外空間時，用 slow 把要留的元素依序寫回原陣列前段，回傳新長度
前綴和pre[i] = a[0] + … + a[i-1]，長度 n+1、pre[0] = 0。區間 [l, r] 的和 = pre[r+1] - pre[l]
差分陣列前綴和的反操作。對區間 [l, r] 全部加 v：d[l] += v、d[r+1] -= v，最後對 d 做一次前綴和還原。多次區間加值、最後才查詢時用
二維前綴和S[i][j] 為左上角矩形和；子矩形和 = 大矩形 − 上 − 左 ＋ 左上（容斥）

L2為什麼

  • 對撞指標為什麼不會漏掉答案？已排序時，若 a[l] + a[r] < target，那 a[l] 跟 r 左邊任何一個配都更小，a[l] 不可能是答案的一部分，可以安心 l++。反之 r--。每步排除一個元素，最多 n 步。
  • 盛水容器為什麼移較矮的那邊？面積 = 寬 × 較矮那邊的高。寬一定會縮小；移較高的那邊，高度上限仍被較矮那邊卡住，面積只會變小。只有移較矮的那邊才有機會變大。
  • 前綴和為什麼要開 n+1 格？多一格 pre[0] = 0，從索引 0 開始的區間就不必特別處理，公式統一成 pre[r+1] - pre[l]。
  • 差分陣列何時不夠用？它適合「先改很多次、最後查一次」。如果改和查交錯進行，每次查都要重算前綴和，就退化成 O(n)；這時要用 Fenwick tree（樹狀陣列）或線段樹，改和查都 O(log n)。
  • 前綴和與滑動視窗的分工？滑動視窗需要「視窗變大，條件只會變得更難／更容易」的單調性；陣列有負數時區間和不單調，視窗就失效，要改用前綴和＋hash（P04）。

對撞指標：已排序陣列找兩數和

def two_sum_sorted(a, target):
    l, r = 0, len(a) - 1
    while l < r:
        s = a[l] + a[r]
        if s == target: return [l, r]
        if s < target: l += 1    # a[l] 配誰都太小，排除
        else:          r -= 1    # a[r] 配誰都太大，排除
    return [-1, -1]

快慢指標：原地刪除已排序陣列的重複值，回傳新長度

def remove_duplicates(a):
    slow = 0                       # 下一個要寫入的位置
    for fast in range(len(a)):
        if fast == 0 or a[fast] != a[fast - 1]:
            a[slow] = a[fast]
            slow += 1
    return slow

P02滑動視窗

一句話：處理「連續子陣列／子字串」時，右邊界一路往右擴，條件不成立時左邊界往右縮。左右邊界都只往右走，每個元素最多進出視窗各一次，所以是 O(n)。主圖的「滑動視窗逐步」就是這個過程。

L1是什麼

名詞意思
固定視窗長度固定為 k：每步加進右邊一個、移除左邊一個。典型：長度 k 的最大平均、字串裡找異位詞（固定長度的計數比對）
可變視窗右邊界每步 +1；while 視窗不合法就左邊界 +1。典型：最長無重複字元子字串、最小覆蓋子字串
收縮條件求最長：不合法時縮到合法，縮完再更新答案。求最短：合法時先更新答案，再縮，一直縮到不合法
視窗計數 map用 hash 記視窗內每個字元的次數；「視窗內有幾種字元」看 map 的 key 數，次數歸零時要把 key 刪掉
單調佇列求「每個長度 k 視窗的最大值」：deque 裡存索引、對應的值由前往後遞減；隊頭就是當前視窗最大值

L2為什麼

  • 為什麼兩層迴圈還是 O(n)？外層 r 走 n 次；內層 while 雖然看起來是迴圈，但 l 整個過程只會往右、總共最多走 n 次。總工作量是 2n，這叫攤銷分析（P14）。
  • 什麼時候不能用滑動視窗？要有單調性：視窗擴大時，「是否合法」只能朝一個方向變。全是正數的「和 ≥ target 的最短子陣列」可以；有負數的「和 = k 的子陣列個數」不行（加一個負數總和反而變小），改用前綴和＋hash（P04）。
  • 「恰好 K 種」怎麼做？「恰好 K」沒有單調性，但「至多 K」有。答案 = atMost(K) - atMost(K-1)。
  • 單調佇列為什麼可以把比新元素小的直接丟掉？新元素比它晚離開視窗、又比它大，只要新元素還在，那個舊元素就永遠不可能成為最大值。每個索引進出 deque 各一次，所以整體 O(n)，比每個視窗掃一次的 O(nk) 快。

可變視窗：最長無重複字元子字串（主圖示範的就是這段）

def longest_unique(s):
    seen = set()
    l = best = 0
    for r, ch in enumerate(s):
        while ch in seen:          # 不合法 → 縮左邊直到合法
            seen.remove(s[l])
            l += 1
        seen.add(ch)
        best = max(best, r - l + 1)  # 求最長：縮完再更新
    return best

單調佇列：每個長度 k 視窗的最大值

from collections import deque
def max_sliding_window(a, k):
    dq, out = deque(), []          # 存索引，對應值遞減
    for i, x in enumerate(a):
        while dq and a[dq[-1]] <= x: dq.pop()   # 比 x 小的永遠當不了最大
        dq.append(i)
        if dq[0] <= i - k: dq.popleft()          # 隊頭滑出視窗
        if i >= k - 1: out.append(a[dq[0]])
    return out

P03二分搜尋

一句話：二分搜尋的本質不是「在排序陣列找一個數」，而是找一個判斷式從 false 變成 true 的分界點。只要答案空間有這種單調性（排序陣列、或「容量越大越裝得下」），就能每次丟掉一半。基本版的逐步動畫在 H 章主圖。

L1是什麼

名詞意思
閉區間寫法範圍 [lo, hi]：while lo <= hi，更新 lo = mid + 1／hi = mid - 1。找「某個值在不在」最直覺
左閉右開寫法範圍 [lo, hi)：hi 初值 n、while lo < hi，更新 lo = mid + 1／hi = mid。找分界點最不容易錯，結束時 lo == hi 就是答案
lower_bound第一個 ≥ x 的位置（Python bisect_left、C++ std::lower_bound）
upper_bound第一個 > x 的位置（Python bisect_right）。x 出現的次數 = upper − lower
對答案二分答案本身有範圍、而且「答案 = m 可不可行」是單調的，就二分 m。典型：Koko 吃香蕉、D 天內送完貨的最小載重、分割陣列的最大值最小
旋轉排序陣列例如 [4,5,6,7,0,1,2]。從 mid 切開，一定有一半是排好的，判斷目標在不在排好的那半，就知道丟哪邊

L2為什麼

  • 為什麼左閉右開比較不會錯？迴圈不變式很單純：lo 左邊全部 false、hi 以右全部 true。每一步只要問 check(mid)：true 就 hi = mid（mid 可能就是答案，不能丟），false 就 lo = mid + 1。結束時 lo 正好是第一個 true。
  • 為什麼有時會死迴圈？寫成 lo = mid 時，若 hi = lo + 1，mid = (lo + hi) // 2 永遠等於 lo，範圍不再縮小。要嘛改用上面的 lo = mid + 1 模板，要嘛取上中位數 mid = (lo + hi + 1) // 2。
  • 對答案二分的複雜度？二分 log(答案範圍) 次，每次跑一遍 O(n) 的 check，總共 O(n log 範圍)。範圍到 10⁹ 也只要約 30 次。
  • 旋轉陣列有重複值時？a[lo] == a[mid] == a[hi] 時分不出哪半排好，只能 lo++、hi--，最壞退化成 O(n)。
  • 中點溢位：C#／C++／Java 用 lo + (hi - lo) / 2，不要 (lo + hi) / 2（理由見 H06）。Python 整數無上限，沒有這個問題。

萬用模板：找第一個讓 check 為 true 的位置（左閉右開）

def first_true(lo, hi, check):     # 在 [lo, hi) 找；全 false 回傳 hi
    while lo < hi:
        mid = (lo + hi) // 2
        if check(mid): hi = mid      # mid 可能是答案，保留
        else:          lo = mid + 1  # mid 不是，丟掉
    return lo

# lower_bound：first_true(0, len(a), lambda i: a[i] >= x)
# 對答案二分：first_true(1, max(piles) + 1, lambda k: hours(k) <= h)

L3出問題怎麼辦

現象最可能原因對策
只剩兩個元素時程式卡住lo = mid 搭配下取整的 mid改用 lo = mid + 1 的模板，或 mid 取上中位數
找第一個出現位置，卻回傳中間某個重複值用了「找到就 return」的版本改找 lower_bound：找到也不停，繼續往左縮

P04雜湊與計數

一句話：用 hash 把「找有沒有某個值」從 O(n) 降到平均 O(1)，代價是額外 O(n) 的記憶體、而且沒有順序。最經典的兩招是 Two Sum（邊走邊查「我需要的另一半出現過沒」）和前綴和＋hash（查「有沒有一個更早的前綴和剛好差 k」）。

L1是什麼

名詞意思
Two Sum 型走到 x 時，查 target - x 有沒有在 map 裡；沒有就把 x → 索引 存進去。一趟 O(n)
前綴和＋hash「和為 k 的子陣列有幾個」：走到前綴和 p 時，答案加上 count[p - k]，再把 count[p] 加 1。count 初值 {0: 1}
頻率統計Python collections.Counter、C# Dictionary<T,int>。異位詞分組：用排序後的字串或 26 格計數 tuple 當 key
去重set／HashSet<T>。最長連續序列：放進 set 後，只從「x-1 不在 set 裡」的起點往上數，整體 O(n)

L2為什麼

  • Two Sum 為什麼要「先查再存」？先存再查的話，target = 2x 時 x 會跟自己配對。先查，map 裡只有「前面」的元素，自然不會用到同一個。
  • 前綴和＋hash 為什麼要 {0: 1}？區間 [i, j] 的和 = pre[j+1] - pre[i]。從索引 0 開始的子陣列對應 pre[0] = 0，不先放進去就會漏掉「從頭開始剛好等於 k」的那幾個。
  • hash 和排序＋雙指標怎麼選？hash：O(n) 時間、O(n) 空間、保留原索引。排序＋雙指標：O(n log n) 時間、O(1) 額外空間、但原索引會亂。題目要回傳索引 → hash；要求不用額外空間 → 排序。
  • hash 平均 O(1)，最壞呢？大量碰撞時退化成 O(n)。要「有順序」或「找範圍」時改用平衡樹（C# SortedDictionary，O(log n)）。

前綴和＋hash：和為 k 的子陣列個數（可以有負數）

def subarray_sum(a, k):
    count = {0: 1}                  # 空前綴，處理從頭開始的子陣列
    p = ans = 0
    for x in a:
        p += x
        ans += count.get(p - k, 0)  # 之前有幾個前綴和剛好差 k
        count[p] = count.get(p, 0) + 1
    return ans

現象最可能原因對策

Python 丟 TypeError: unhashable type: 'list'拿 list 當 dict 的 key改成 tuple
C# 丟 KeyNotFoundException用索引子讀不存在的 key改 TryGetValue 或 GetValueOrDefault
Two Sum 回傳兩個相同索引先存再查改成先查再存

P05堆疊與單調堆疊

一句話：堆疊處理「最近一個還沒配對的東西」（括號、函式呼叫、復原）。單調堆疊是堆疊裡保持遞增或遞減，用來在 O(n) 內替每個元素找到「左邊／右邊第一個比我大（或小）的」。主圖的「單調堆疊逐步」示範每日溫度。

L1是什麼

名詞意思
括號配對左括號 push；右括號時看堆疊頂是不是對應的左括號，是就 pop。結束時堆疊要是空的
下一個更大元素維持一個值遞減的堆疊（存索引）。新元素比堆疊頂大 → 堆疊頂的「下一個更大」就是它，pop 並記錄；重複到不再比較大，再 push
每日溫度同上，答案是索引差：ans[j] = i - j
柱狀圖最大矩形維持高度遞增的堆疊。被 pop 的柱子 h：右邊界是現在的 i（第一個比它矮的），左邊界是 pop 後的新堆疊頂；寬 = i - 新頂 - 1
哨兵在陣列尾端補一個 0（或極小值），保證最後所有元素都會被 pop、被結算

L2為什麼

  • 為什麼是 O(n)？每個索引最多 push 一次、pop 一次，總操作 2n。跟滑動視窗一樣是攤銷分析。
  • 要遞增還是遞減？找「下一個更大」→ 堆疊遞減（被更大的人踢出時就找到答案）。找「下一個更小」→ 堆疊遞增。口訣：誰把你踢出去，誰就是你的答案。
  • 為什麼存索引不存值？大部分題目要的是距離或寬度；存索引可以從 a[i] 取回值，反過來不行。
  • pop 之後的新堆疊頂代表什麼？是被 pop 的元素「左邊第一個比它小（或大）的」。所以一次掃描可以同時得到左右邊界，最大矩形就是靠這個。

單調堆疊：每日溫度（主圖示範的就是這段）

def daily_temperatures(t):
    ans = [0] * len(t)
    st = []                          # 存索引，溫度由底到頂遞減
    for i, x in enumerate(t):
        while st and t[st[-1]] < x:  # x 把比它冷的都踢出去
            j = st.pop()
            ans[j] = i - j           # 誰踢你，誰就是你的答案
        st.append(i)
    return ans                       # 留在堆疊裡的：沒有更暖的一天，維持 0

P06鏈結串列

一句話：鏈結串列題的難處不是演算法，而是指標順序：改 next 之前要先存好下一個節點，不然後面整串就丟了。兩個萬用工具：dummy head（不必特別處理頭節點）和快慢指標（找中點、找環、找倒數第 n 個）。

L1是什麼

名詞意思
dummy head在頭前面放一個假節點，dummy.next = head。刪除頭節點、合併串列時不必寫特例，最後回傳 dummy.next
反轉三個指標 prev / cur / nxt：nxt = cur.next; cur.next = prev; prev = cur; cur = nxt，O(n) 時間、O(1) 空間
找中點slow 一次走 1、fast 一次走 2，fast 到底時 slow 在中間
Floyd 找環同上兩個速度，有環就一定會相遇；相遇後一個回到 head，兩個都一次走 1，再相遇處就是環的入口
倒數第 n 個fast 先走 n 步，再一起走；fast 到底時 slow 就在倒數第 n 個的前一個（從 dummy 出發時）
合併兩條已排序串列dummy＋tail，每次接較小的那個；一條用完就把另一條整串接上

L2為什麼

  • 為什麼有環一定會相遇？進入環以後，fast 每步比 slow 多走 1，兩者的距離每步縮短 1，不會跳過，所以一定會相遇。
  • 為什麼相遇後從 head 再走，會停在環入口？設 head 到入口距離 a、入口到相遇點 b、環長 c。fast 走的是 slow 的兩倍：2(a+b) = a+b+kc，得 a = kc - b。從相遇點再走 a 步，等於繞 k 圈再退 b 步，剛好回到入口；從 head 走 a 步也到入口。
  • 偶數長度時中點是哪個？while fast and fast.next 停下時，slow 在後半段第一個；要前半段最後一個就改成 while fast.next and fast.next.next。回文串列、重排串列要把串列切成兩半時，這個差別很關鍵。
  • 鏈結串列 vs 陣列：已經拿到節點時，插入刪除 O(1)；但沒有隨機存取（找第 k 個要 O(k)），節點分散在記憶體裡，cache 命中率差。實務上大多數情況陣列（List<T>）更快。

反轉鏈結串列

def reverse(head):
    prev, cur = None, head
    while cur:
        nxt = cur.next      # 1. 先存下一個
        cur.next = prev     # 2. 指回去
        prev, cur = cur, nxt  # 3. 往前走
    return prev

P07樹與遞迴

一句話：樹的題目幾乎都是同一個問題：「這個節點要從左右子樹拿到什麼資訊，又要回傳什麼給父節點？」想清楚回傳值，遞迴就自己寫出來了。要一層一層處理時改用 BFS。

L1是什麼

名詞意思
前序／中序／後序根在「前、中、後」被處理：前序 根左右、中序 左根右、後序 左右根。BST 的中序走訪是排好序的
層序走訪（BFS）用 queue；每一層開始時先記下 len(queue)，只處理這麼多個，就能分層。典型：右視圖、每層平均、最小深度
深度 vs 高度深度：從根往下數；高度：從葉往上數。遞迴回傳高度最常見：1 + max(左, 右)
BST 性質左子樹全部小於根、右子樹全部大於根（不只是直接的子節點）
LCA（最近共同祖先）兩個節點往上走第一個交會的祖先。一般二元樹用後序遞迴；BST 直接比大小

L2為什麼

  • DFS 回傳值怎麼設計？以「二元樹直徑」為例：答案是某個節點的「左高度＋右高度」，但父節點需要的是「我的高度」。所以函式回傳高度，順便用一個外部變數更新最大直徑。回傳給父節點的，和題目要的答案常常不是同一個東西。
  • 什麼時候用後序？需要先知道子樹的結果才能算自己時（高度、直徑、子樹和、平衡判斷、LCA）。前序適合由上往下帶資訊（目前路徑和、上下界）。
  • 驗證 BST 為什麼要帶上下界？只比對直接子節點會漏掉這種情況：根 5、右子 6、6 的左子 3。3 < 6 沒錯，但 3 在 5 的右子樹裡，違反 BST。遞迴時要往下傳 (low, high)，或檢查中序是否嚴格遞增。
  • 一般二元樹的 LCA 為什麼這樣寫就對？遇到 p 或 q 就回傳自己；左右兩邊都找到東西，代表 p、q 分在兩側，目前節點就是 LCA；只有一邊找到，就把那邊的結果往上傳。
  • 遞迴深度：等於樹高。平衡樹約 log n，但退化成一條線的樹是 n；Python 預設遞迴上限約 1000，深度可能很大時改成迭代＋顯式 stack（H06）。

回傳值設計：二元樹直徑

def diameter(root):
    best = 0
    def height(node):
        nonlocal best
        if not node: return 0
        l, r = height(node.left), height(node.right)
        best = max(best, l + r)     # 題目要的：經過這個節點的最長路徑
        return 1 + max(l, r)        # 父節點要的：我的高度
    height(root)
    return best

現象最可能原因對策
驗證 BST 對某些樹誤判為合法只比較直接子節點往下傳上下界，或檢查中序是否嚴格遞增
層序走訪分層錯亂迴圈裡直接用 len(queue) 判斷，但 queue 在迴圈中被加長了每層開始時先把 size = len(queue) 存下來
單獨跑對、送出後某些測資答案怪答案存在類別屬性或全域變數，多筆測資之間沒重設用區域變數＋nonlocal，或每次呼叫開頭重設
最小深度回傳 1，但樹明明更深把只有一邊子樹的節點當成葉子（min(左, 右) 取到空的那邊的 0）只有左右都空才算葉子；有一邊空就只看另一邊
退化樹（一條線）時遞迴爆掉深度等於節點數改迭代，或用 BFS

P08圖

一句話：格子、人際關係、課程先修、城市道路，都是「點＋邊」。先決定要回答什麼：最少幾步用 BFS、有幾塊連在一起用 DFS 或 Union-Find、先後順序用拓撲排序、帶權重的最短路用 Dijkstra。

L1是什麼

名詞意思
鄰接表graph[u] = [v1, v2, …]。空間 O(V+E)，大多數題目都用這個；鄰接矩陣是 O(V²)，只在點很少或圖很密時用
BFS 最短路無權重（每步成本相同）的圖，BFS 第一次碰到某點時的層數就是最短距離。典型：迷宮最少步數、單字接龍
DFS 連通分量從每個沒走過的點出發，把能到的全部標記，出發幾次就有幾塊。典型：島嶼數量
拓撲排序（Kahn）有向圖：入度為 0 的點進 queue，取出時把它指向的點入度減 1，減到 0 就進 queue。輸出的點數少於 V 代表有環。典型：課程表
Union-Find（並查集）find(x) 找代表、union(a, b) 合併兩群。加上路徑壓縮與依大小合併，每次操作近乎 O(1)（反阿克曼函數 α(n)）
Dijkstra權重不能為負的最短路：用 min-heap 每次取目前距離最小的點去鬆弛鄰居，O((V+E) log V)

L2為什麼

  • BFS 為什麼保證最短？它是一層一層往外擴：先走完所有距離 1 的點，才會碰到距離 2 的點。第一次到達時，不可能有更短的路還沒走。
  • visited 為什麼要在「放進 queue 時」標記？如果等到取出時才標記，同一個點可能被好幾個鄰居重複放進 queue，格子題會多出好幾倍的工作量而超時。
  • Dijkstra 為什麼不能有負權重？它假設「從 heap 取出的點，距離已經是最終答案」。有負邊時，之後可能經由一條負邊繞回來變得更短，這個假設就破了。有負邊要用 Bellman-Ford（O(VE)）。
  • Union-Find 和 DFS 怎麼選？圖一次給完、只問一次 → DFS 簡單。邊是一條一條加進來、而且每加一條都要問「這兩點連通了沒」→ Union-Find。「冗餘連線」那種題（找出造成環的那條邊）也是 Union-Find 最直接。
  • 格子就是圖：每格是點，上下左右是邊。用方向陣列 [(1,0),(-1,0),(0,1),(0,-1)] 走，記得檢查越界。

BFS：格子最少步數（放進 queue 時就標記）

from collections import deque
def shortest(grid, start, goal):
    R, C = len(grid), len(grid[0])
    q, seen = deque([(start, 0)]), {start}
    while q:
        (r, c), d = q.popleft()
        if (r, c) == goal: return d
        for dr, dc in ((1,0), (-1,0), (0,1), (0,-1)):
            nr, nc = r + dr, c + dc
            if 0 <= nr < R and 0 <= nc < C and grid[nr][nc] == 0 and (nr, nc) not in seen:
                seen.add((nr, nc))          # 放進去就標記
                q.append(((nr, nc), d + 1))
    return -1

Union-Find：路徑壓縮＋依大小合併

parent = list(range(n)); size = [1] * n
def find(x):
    while parent[x] != x:
        parent[x] = parent[parent[x]]   # 路徑壓縮（隔代指）
        x = parent[x]
    return x
def union(a, b):
    ra, rb = find(a), find(b)
    if ra == rb: return False           # 已經同一群 → 這條邊造成環
    if size[ra] < size[rb]: ra, rb = rb, ra
    parent[rb] = ra; size[ra] += size[rb]
    return True

P09回溯

一句話：回溯就是有系統地試遍所有選擇：做一個選擇 → 遞迴往下 → 撤銷選擇，換下一個。題目要「列出所有」方案時用它；複雜度是指數級，所以 n 通常很小（≤ 20 左右）。

L1是什麼

名詞意思
基本骨架選擇 → backtrack(...) → 撤銷。狀態（目前路徑）只有一份，靠撤銷還原
子集帶 start 參數，只往後選；每個節點都是一個答案。共 2ⁿ 個
組合同子集，但路徑長度到 k 才收進答案。可剪枝：剩下的數不夠湊滿 k 就停
排列不帶 start，每層從頭選；用 used[] 標記已用過的。共 n! 個
剪枝提早判斷「這條路不可能成功」就不往下走。例：組合總和題，先排序，目前和超過 target 就 break
重複元素去重先排序，同一層裡 if i > start and a[i] == a[i-1]: continue

L2為什麼

  • 收答案時為什麼要複製一份？path 只有一份，之後會被撤銷、改掉。直接 res.append(path) 存的是同一個物件的參考，最後全部變成空 list。要 res.append(path[:])（C# 是 new List<int>(path)）。
  • 去重為什麼是「同一層」跳過，不是「同一條路」跳過？例如 [1, 2, 2']：同一條路先選 2 再選 2' 是合法的 [1,2,2]；但在同一層，選 2 和選 2' 開出來的子樹完全一樣，第二個要跳過。i > start 這個條件就是在說「不是這一層第一個」。
  • 子集和排列為什麼寫法不同？子集、組合不在乎順序，start 保證只往後選，[1,2] 和 [2,1] 不會都出現；排列在乎順序，每層都要從頭看，靠 used 避免重複使用同一個元素。
  • 回溯 vs DP：要列出每一個方案 → 回溯（答案本身就有指數個）。只要數量或最佳值，而且子問題會重複 → 通常改 DP，從指數降到多項式。

回溯骨架：有重複元素的子集

def subsets_with_dup(a):
    a.sort()
    res, path = [], []
    def bt(start):
        res.append(path[:])               # 每個節點都是答案；要複製
        for i in range(start, len(a)):
            if i > start and a[i] == a[i-1]: continue   # 同一層去重
            path.append(a[i])             # 選擇
            bt(i + 1)                     # 往下
            path.pop()                    # 撤銷
    bt(0)
    return res

現象最可能原因對策

超時沒剪枝；或題目其實只問數量排序後超過就 break；只問數量就改 DP
結果亂七八糟、出現不該有的元素某個分支 return 前沒撤銷（例如 used[i] 沒改回 false）選擇和撤銷成對寫，中間不要提早 return

P10動態規劃

一句話：DP 是「把大問題拆成會重複出現的小問題，每個只算一次、存起來」。寫 DP 的五個步驟：狀態定義（dp[i] 代表什麼）→ 轉移式（dp[i] 從誰來）→ 初始值 → 計算順序 → 答案在哪一格。狀態定義對了，其他四步通常就順了。

L1是什麼

名詞意思
狀態定義用一句話講清楚 dp[i]（或 dp[i][j]）代表什麼。例：「以第 i 個結尾的最長遞增子序列長度」
轉移式例：爬樓梯 dp[i] = dp[i-1] + dp[i-2]；打家劫舍 dp[i] = max(dp[i-1], dp[i-2] + a[i])
Top-down vs Bottom-upTop-down：遞迴＋memo（Python @cache），好寫。Bottom-up：迴圈填表，沒有遞迴深度問題、容易壓空間
滾動陣列dp[i] 只依賴 dp[i-1]（或前兩格）時，只留需要的那幾格，空間從 O(n) 降到 O(1)，二維降到一維
0/1 背包每個物品最多拿一次：dp[j] = max(dp[j], dp[j-w] + v)，j 由大到小跑
完全背包每個物品可拿無限次：同一個式子，j 由小到大跑。典型：零錢兌換
LIS／LCS最長遞增子序列：O(n²) 的 DP，或 O(n log n) 的「tails 陣列＋二分」。最長共同子序列：dp[i][j] 看兩字串前 i、j 個字元
區間 DPdp[i][j] 代表區間 [i, j] 的答案，按區間長度由短到長填。典型：最長回文子序列、戳氣球

L2為什麼

  • 什麼時候能用 DP？兩個條件：重疊子問題（同一個小問題被問很多次，例如暴力費氏數列）和最佳子結構（大問題的最佳解由小問題的最佳解組成）。
  • 0/1 背包為什麼 j 要倒著跑？一維陣列裡，dp[j-w] 應該是「還沒考慮這個物品」時的值。正著跑的話，dp[j-w] 已經在這一輪被更新過（已經拿過這個物品），等於同一個物品拿了兩次，就變成完全背包。
  • 零錢「組合數」和「排列數」差在迴圈順序：外層跑硬幣、內層跑金額 → 每種硬幣依序考慮，1+2 和 2+1 只算一次（組合）。外層跑金額、內層跑硬幣 → 順序不同算不同（排列）。
  • 為什麼貪婪不行、要 DP？硬幣 {1, 3, 4} 湊 6：貪婪先拿最大的 4，得到 4+1+1 共 3 枚；最佳解是 3+3 共 2 枚。貪婪只看眼前，DP 會比較所有拆法。
  • LIS 的 O(n log n) 怎麼來？tails[k] 存「長度為 k+1 的遞增子序列，最小可能的結尾」。這個陣列是遞增的，所以每個新數字用二分（P03）找位置替換或接在尾端。

0/1 背包（一維）：容量由大到小

def knapsack(weights, values, cap):
    dp = [0] * (cap + 1)            # dp[j]：容量 j 時的最大價值
    for w, v in zip(weights, values):
        for j in range(cap, w - 1, -1):   # 倒著跑，每個物品只用一次
            dp[j] = max(dp[j], dp[j - w] + v)
    return dp[cap]

零錢兌換（最少枚數，完全背包）：初始值是重點

def coin_change(coins, amount):
    INF = float('inf')
    dp = [0] + [INF] * amount       # 求最小 → 初值無限大；湊 0 元要 0 枚
    for c in coins:
        for j in range(c, amount + 1):    # 正著跑，硬幣可重複用
            dp[j] = min(dp[j], dp[j - c] + 1)
    return dp[amount] if dp[amount] != INF else -1

P11貪婪與區間

一句話：貪婪是「每一步都拿當下看起來最好的，而且不回頭」。它很快（通常就是一次排序 O(n log n)），但不一定對。用之前先想一個反例；想不到反例、又能用「交換論證」說服自己，才放心用。

L1是什麼

名詞意思
區間排程（最多不重疊）依結束時間排序，能放就放。典型：無重疊區間（要刪幾個）、射氣球
區間合併依開始時間排序，下一個的開始 ≤ 目前的結束就合併、結束取較大
會議室數量同時重疊最多幾個：開始、結束時間分開排序後掃描；或依開始排序＋min-heap 存結束時間
跳躍遊戲維護「目前能到的最遠位置」，掃描時若 i 超過它就到不了
反例檢驗拿小例子試貪婪規則，找一個讓它失敗的輸入。找到就改用 DP

L2為什麼

  • 區間排程為什麼依結束時間排，不依開始時間？選最早結束的，留給後面的空間最多。依開始時間排會挑到「很早開始但拖很長」的區間，一個佔掉好幾個的位置。反例：[1,10]、[2,3]、[4,5]，依開始時間會選 [1,10] 只放得下 1 個，依結束時間可以放 2 個。
  • 交換論證是什麼？假設最佳解第一個選的不是貪婪選的那個，把它換成貪婪選的，結果不會變差。一路換下去，就證明貪婪解至少一樣好。
  • 區間合併為什麼依開始時間？依開始排序後，能跟目前區間合併的一定緊接在後面，一次掃描就能處理完。
  • 端點相碰算不算重疊？[1,2] 和 [2,3]：會議室題通常算不重疊（2 點結束就能接 2 點開始）；合併區間題通常算重疊。看題目，決定用 < 還是 <=。

區間排程：最多能留幾個不重疊的區間

def max_non_overlap(iv):
    iv.sort(key=lambda x: x[1])     # 依結束時間
    cnt, end = 0, float('-inf')
    for s, e in iv:
        if s >= end:                # 端點相碰算不重疊（依題意調整）
            cnt += 1; end = e
    return cnt

P12Heap 與 Top-K

一句話：Heap（優先佇列）能在 O(log n) 內加入元素、在 O(1) 內看到最小（或最大）值。題目一出現「前 K 大」「第 K 小」「一直有新資料、隨時要最值」，就想到它。

L1是什麼

名詞意思
二元 heap完全二元樹存在陣列裡，父節點 ≤ 子節點（min-heap）。push／pop O(log n)、看頂端 O(1)、把整個陣列建成 heap（heapify）O(n)
Python heapq只有 min-heap；要 max-heap 就把值取負號存進去
C# PriorityQueue<TElement, TPriority>.NET 6 起內建，min-heap；要最大就傳反向的 comparer
Top-K 大維持大小為 k 的 min-heap：新元素比頂端大就換掉頂端。O(n log k)
合併 K 條排序串列把每條的頭放進 heap，每次取最小的，再把它的下一個放進去。O(N log k)
資料流中位數兩個 heap：左半用 max-heap、右半用 min-heap，保持兩邊大小差 ≤ 1，中位數在兩個頂端

L2為什麼

  • 找前 K 大為什麼用 min-heap？heap 裡放的是「目前的前 K 名」，頂端是其中最小的那個，也就是入圍門檻。新來的比門檻大才有資格進來，把門檻踢掉。heap 永遠只有 k 個，所以每次操作是 log k 而不是 log n。
  • Heap、排序、Quickselect 怎麼選？全部排序 O(n log n) 最簡單；k 遠小於 n 或資料是串流 → heap O(n log k)；只要第 K 個、不要順序 → Quickselect 平均 O(n)、最壞 O(n²)。
  • heapify 為什麼是 O(n) 不是 O(n log n)？由下往上調整，大部分節點在底層、只需要往下調一兩層，加總起來是 O(n)。
  • 雙 heap 為什麼能 O(1) 取中位數？左邊 max-heap 的頂端是左半最大、右邊 min-heap 的頂端是右半最小，中位數就是其中一個或兩者平均。每次插入 O(log n)。

Top-K 大：大小為 k 的 min-heap

import heapq
def top_k(a, k):
    h = []
    for x in a:
        if len(h) < k: heapq.heappush(h, x)
        elif x > h[0]: heapq.heapreplace(h, x)   # 比門檻大才換
    return sorted(h, reverse=True)

P13位元運算

一句話：把整數當成一排開關。三個最常用的性質：相同的數 XOR 會抵銷、x & (x-1) 會關掉最低位的 1、x & -x 會只留下最低位的 1。n ≤ 20 的「哪些元素被選了」可以用一個整數表示，這叫位元遮罩。韌體 register 操作也用同一套（K02）。

L1是什麼

運算效果與典型用途
a ^ a = 0、a ^ 0 = aXOR 可交換、可結合，成對的數全部抵銷。典型：只出現一次的數字、找缺少的數字
x & (x - 1)關掉最低位的 1。用途：數有幾個 1（迴圈做到 0 為止）；判斷 2 的冪：x > 0 and x & (x-1) == 0
x & -x（lowbit）只留下最低位的 1。Fenwick tree（樹狀陣列）的核心
(mask >> i) & 1第 i 位是不是 1（第 i 個元素有沒有被選）
mask | (1 << i)、mask & ~(1 << i)把第 i 位設 1／清 0
for m in range(1 << n)列舉 n 個元素的全部 2ⁿ 個子集

L2為什麼

  • x & -x 為什麼只留最低位？二補數裡 -x = ~x + 1。取反後最低位的 1 變成 0、它右邊的 0 全變成 1；加 1 會一路進位，剛好把那一位變回 1，其餘位都和 x 相反，AND 起來只剩那一位。
  • 只出現一次的數字為什麼一路 XOR 就好？XOR 不在乎順序，出現兩次的都兩兩抵銷成 0，最後剩下的就是只出現一次的那個。O(n) 時間、O(1) 空間，比 hash 省記憶體。
  • 位元遮罩 DP：n ≤ 20 左右時，用 dp[mask] 表示「已選了 mask 這些元素」的最佳值，狀態數 2ⁿ ≈ 100 萬。旅行推銷員問題就是 dp[mask][最後停在哪]，O(2ⁿ·n²)。
  • 運算子優先順序陷阱（C／C#／C++）：x & 1 == 0 會被解讀成 x & (1 == 0)，因為 == 比 & 優先。1 << i + 1 是 1 << (i + 1)。位元運算一律加括號。

只出現一次的數字／數 1 的個數

from functools import reduce
single = reduce(lambda a, b: a ^ b, nums)

def popcount(x):
    c = 0
    while x:
        x &= x - 1      # 每次關掉一個 1
        c += 1
    return c            # Python 3.10+ 可直接 x.bit_count()

P14從限制反推解法

一句話：題目最下面的 Constraints（例如 1 <= n <= 10^5）其實是提示：一般線上評測約 1～2 秒，大約能跑 10⁸ 次簡單運算（數量級粗估），由 n 就能反推出可以接受的複雜度，再從複雜度推回可能的套路。Big-O 本身的觀念見 H06。

L1是什麼

n 的範圍可接受的複雜度常見套路
n ≤ 10O(n!)全排列、回溯暴力（P09）
n ≤ 20O(2ⁿ)、O(2ⁿ·n)子集列舉、位元遮罩 DP（P13）
n ≤ 500O(n³)區間 DP、Floyd 全點對最短路
n ≤ 5,000O(n²)二維 DP（LCS）、雙層迴圈
n ≤ 10⁵～10⁶O(n log n)、O(n)排序、heap、二分、雙指標、滑動視窗、hash、單調堆疊
n ≥ 10⁹O(log n)、O(1)對答案二分、數學公式、快速冪

L2為什麼

  • 攤銷分析：看的是「整個過程的總成本」，不是單一步的最壞情況。動態陣列 append 偶爾要搬全部（O(n)），但攤到每次只有 O(1)；滑動視窗、單調堆疊的內層 while 也是一樣：每個元素總共只進出一次。攤銷是保證的總量，跟「平均情況」（靠運氣，如 hash 不碰撞）不同。
  • 遞迴的複雜度怎麼算？寫出遞迴式：merge sort 是 T(n) = 2T(n/2) + O(n) → O(n log n)；二分是 T(n) = T(n/2) + O(1) → O(log n)；樹的 DFS 每個節點一次 → O(n)。暴力費氏數列 T(n) = T(n-1) + T(n-2) 是指數級，加 memo 後變 O(n)。
  • DP 的複雜度 = 狀態數 × 每個狀態的轉移成本。例：LCS 有 m×n 個狀態、每個 O(1) 轉移 → O(mn)；LIS 的 O(n²) 版是 n 個狀態、每個看前面全部 → O(n²)。
  • 空間也要算：遞迴深度會佔 stack（樹高、回溯深度），DP 表格可能 O(n²)。滾動陣列可以把 DP 的空間壓下來（P10）。
